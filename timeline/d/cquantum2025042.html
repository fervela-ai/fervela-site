AWS 的金鑰管理等三項服務，改用 ML-KEM 混合後量子 TLS

AWS 把已標準化的後量子金鑰封裝演算法放進三項最敏感的服務，並公布實測的效能代價。

這是什麼

ML-KEM 是 NIST 標準化的後量子金鑰封裝機制，用來防範「先收集加密流量、等量子電腦成熟再解密」的攻擊。混合式做法是把傳統橢圓曲線金鑰協商和 ML-KEM 並用。

三點帶走

  1. KMS、ACM、Secrets Manager 端點已支援 ML-KEM 混合金鑰協商。
  2. 預設設定下效能影響約 0.05%，最壞情況約 2.3%。
  3. Kyber 支援 2025 年底前保留，2026 年移除，客戶端要改用 ML-KEM。

重點與分析

官方表示，AWS KMS、AWS Certificate Manager 與 AWS Secrets Manager 的端點，已在 aws 分區所有區域的非 FIPS 端點支援 ML-KEM 混合後量子金鑰協商。

挑這三項服務的理由是官方自己寫的：它們是安全性最關鍵、最急需後量子機密性的服務。範圍上有兩個限制要讀清楚：只涵蓋非 FIPS 端點，且需要客戶端也提供 ML-KEM，才會真的走後量子協商。

官方表示，這三項服務先前已支援 CRYSTALS-Kyber（ML-KEM 的前身），Kyber 支援將持續到 2025 年，2026 年起從所有端點移除。

這是明確的淘汰時程。仍依賴舊版 Kyber 的客戶端要在 2026 年前升級，否則會失去後量子保護。官方同時說，使用正式版 AWS SDK for Java v2 的客戶不需改程式碼就能從 Kyber 升級到 ML-KEM。

官方表示，從純橢圓曲線改為混合協商，握手時多傳約 1600 位元組，並多花約 80 到 150 微秒的運算時間。

這個成本是一次性的連線起始成本，由整條連線的後續請求分攤。數字看起來很小，但對每次都重新握手的短連線服務仍有累積效果，所以官方才補了下面的實測。

官方表示，在 KMS GenerateDataKey 的基準測試中，若完全不重用 TLS 連線，混合後量子 TLS 使每秒交易數平均下降約 2.3%（108.7 降到 106.2）；使用預設的連線重用時只下降 0.05%（216.1 降到 216.0）。

這個測試有清楚的條件：單一執行緒、同區域的 EC2 客戶端與端點，官方自己也說明結果會隨環境不同。它回答的是「會不會明顯變慢」，不是所有工作負載的保證；要判斷自己的服務，還得用自己的流量重測。

官方表示，AWS 的 AWS-LC 密碼學函式庫是第一個把 ML-KEM 納入 FIPS 140-3 驗證的開源密碼模組。

這句話說明實作的來源：AWS-LC 與 s2n-tls 是 AWS 自己維護的開源元件。對外部使用者的意義是可以檢視原始碼，但「第一個」是 AWS 的自我說明，頁面沒有附驗證編號以外的比較對象。

通鑑怎麼看

通鑑認為，這則的可讀性在於它公布了成本數字與淘汰日期，而不只是宣布「支援」。對正在規劃遷移的團隊，真正要做的事是升級客戶端與 SDK，而不是等服務端。
