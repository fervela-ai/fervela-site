Azure Cobalt 100 虛擬機器進入預覽

Arm（ARM） 在官方部落格說明 Microsoft（MSFT） 自研的 Arm 架構處理器 Cobalt 100 如何用於 Azure 虛擬機器。

這是什麼

Cobalt 100 是 Microsoft（MSFT） 自行設計的雲端處理器，建在 Arm（ARM） 的 Neoverse CSS（運算子系統）之上。這是雲端業者自研晶片的案例，與 Google（GOOGL） Axion 屬同一類。

三點帶走

  1. Microsoft（MSFT） 在 Build 預覽三款 Cobalt 100 Azure 虛擬機器。
  2. Cobalt 100 以 Arm（ARM） Neoverse CSS 為基礎。
  3. 文章沒有給核心數、價格與全面提供時間。

重點與分析

官方表示，Microsoft（MSFT） 在 Build 預覽三款 Cobalt 100 Azure 虛擬機器。

三款為通用型 Dpsv6、Dplsv6 與記憶體最佳化的 Epsv6。文章是 Arm（ARM） 的解讀，不是 Microsoft（MSFT） 的規格頁，所以沒有核心數、時脈或價格；『預覽』代表尚非正式上市，何時全面提供原文沒有說。

官方表示，Cobalt 100 以 Arm（ARM） Neoverse CSS 為基礎並客製化。

Neoverse CSS 是 Arm（ARM） 把伺服器核心與互連預先整合的方案，Microsoft（MSFT） 在其上加入自己的設計。Arm 說的效率與效能優勢沒有給比較對象與數字，這一段是定性描述，無法驗證。雲端業者自研處理器的動機通常是控制成本與供應，但本頁並沒有給出任何成本或性價比數字，這部分只能等 Microsoft 公布。

官方表示，這些虛擬機器支援資料庫、網頁伺服器、微服務與 CI/CD 管線。

這份清單說明目標是通用雲端工作而非 AI 訓練，並與 Azure Kubernetes Service 整合。它也顯示軟體相容性是 Arm（ARM） 伺服器能否被採用的關鍵，所以文章花相當篇幅列出受支援的作業系統與工具。

官方表示，開發者可用原生 Arm（ARM） 的 GitHub Actions 執行器編譯並部署到 AKS。

流程是編譯後推送到 Azure Container Registry，再部署在以 Cobalt 100 虛擬機器為節點的 AKS 叢集。這是一條從建置到部署都不經過 x86 轉換的原生流程，對想評估遷移的團隊而言比晶片規格更實用。對工程團隊來說，原生流程的意義在於可以直接在 Arm（ARM） 上測試與驗證，不必在 x86 上交叉編譯，降低上線前的不確定性。

官方表示，Arm（ARM） 同時推出軟體生態系儀表板。

儀表板讓開發者查看哪些軟體套件已支援 Arm（ARM） Neoverse 平台，針對的是遷移障礙：不知道自己用的套件是否支援。儀表板內容與涵蓋範圍原文沒有細節，需另行查證。
