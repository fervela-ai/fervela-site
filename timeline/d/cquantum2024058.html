Qiskit SDK 1.1.0 發佈：型別化古典變數與更快的轉譯器｜IBM Quantum｜5 月 29 日 事件進階

Qiskit 1.1.0：電路能存放即時古典變數，轉譯更快

官方表示，Qiskit SDK v1.1.0 是 1.x 系列的第一個次版本，新增型別化古典變數，並持續把轉譯器改寫為 Rust 以提升速度。

這是什麼

Qiskit 是 IBM 主導的開源量子程式開發套件。轉譯（transpile）指把抽象的量子電路改寫成符合特定量子裝置限制的電路。這份發佈摘要列出 1.1.0 的新功能、效能改善、新的轉譯步驟與棄用項目。

三點帶走

  1. Qiskit 1.1.0 是 1.x 的第一個次版本，官方保證從 1.0 升級不會有破壞性變更。
  2. 電路新增型別化古典變數，但官方說明尚未支援 primitives，屬於鋪路性質。
  3. StarPreRouting 範例的 ecr 閘由 468 降到 194，但這是特定電路的官方範例。

重點與分析

官方表示，v1.1.0 是 Qiskit SDK 第一個主版本下的第一個次版本更新，不會對從 v1.0 升級的使用者引入破壞性變更。

對開發者最實際的訊息是相容性：次版本更新承諾不破壞既有程式，所以升級風險低。這也呼應 1.0 之後走穩定版本號的做法，讓企業與研究團隊可以放心鎖版本。

官方表示，QuantumCircuit 物件現在支援型別化古典變數，可以基本地表示電路執行期間的即時古典運算。

這讓電路可以存放並比較測量結果，用於條件控制流程。但官方同時說明，這只是邁向即時古典運算的第一步，目前尚未支援 primitives 介面，硬體與模擬器後端要完整支援還需要時間。因此它現在更像是給未來動態電路鋪路的語言能力，而非立刻可用的成熟功能。

官方表示，兩量子位元合成程式（TwoQubitWeylDecomposition 與 TwoQubitBasisDecomposer）改以 Rust 重新實作，帶來明顯的執行時間改善。

轉譯在電路變大時很耗時，把效能關鍵的程式碼從 Python 搬到 Rust，是 Qiskit 近期的主軸。文章用圖表比較 v1.0.2 與 v1.1.0 在最佳化等級 2 的轉譯時間，但正文沒有給單一的加速倍數，讀者想知道實際差距得看圖或自己的電路。

官方表示，多控制 X 閘（MCXGate）與相位閘（MCPhaseGate）的合成，閘數減少了超過兩個數量級。

這是文章中少數有明確量級的改善，對使用多控制閘的演算法（如搜尋類演算法的子電路）尤其有感。需要留意的是，這項數字是針對這兩種閘的合成結果，並不表示所有電路的轉譯結果都縮小這麼多。

官方表示，新的 StarPreRouting 轉譯步驟把星狀連接的兩量子位元閘改寫成線性連接序列；文中範例中 ecr 閘數由 468 降到 194。

範例是針對 100 量子位元電路在 ibm_brisbane 上、最佳化等級 3 的輸出計數，ecr 閘約減少 58%（此為依文中兩數字換算）。這是官方挑選的合適案例，不代表所有電路都有相同幅度；星狀連接以外的電路不會有此效果。另外官方也列出 Python 3.8 支援已棄用，以及 Provider 與 ProviderV1 將在 Qiskit 2.0 移除。

通鑑怎麼看

通鑑認為，Qiskit 1.1.0 是穩健的工程更新而非突破：新語言能力是鋪路，效能改善多在轉譯端。對想在 IBM 硬體上跑較大電路的人，轉譯變快、閘數變少是真實的好處，但文中多是挑選的範例，實際收益要用自己的電路驗證。
