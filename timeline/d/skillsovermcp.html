Skills over MCP 讓 Claude 接上工具時，也學會怎麼把工作做完

Anthropic 在產品更新中宣布，MCP 伺服器現在能把操作指引與工具一起交給 Claude，並擴充長時間工作及中途確認的能力。

這是什麼

Skills over MCP 像是工具附上的工作手冊：MCP 伺服器除了讓 Claude 使用工具，也能提供處理特定任務的步驟。Claude 只在需要時載入手冊；伺服器更新時，手冊也會一起更新。目前此功能在 Claude 與 Claude Code 公開測試。

三點帶走

  1. Skills over MCP 讓工具附上工作方法，Claude 在需要時才載入。
  2. Tasks 處理耗時工作；Elicitation 讓使用者在花費、刪除等關鍵步驟作決定。
  3. File Uploads 預計稍後推出，將補上文件類工作所需的檔案傳遞。

重點與分析

工具名稱與說明能告訴 Claude 可以做什麼；Skills over MCP 讓伺服器一併提供實作步驟、最佳做法，或依帳戶與組織編寫的工作指引。

通鑑認為，這解開的是「會按按鈕，卻不知道先後順序」的卡關。完成一件工作，往往需要判斷先查什麼、何時修改，以及每一步該遵守哪些規則；光看工具清單，很難知道這些細節。現在提供工具的一方也能交付操作指引，使用者不必每次都從頭解釋流程。Claude 只在需要時載入指引，則讓工作手冊可以跟著工具走，不必一開始就把所有內容塞進對話。

Anthropic 列出的應用包括：Shopify 協助 Claude 設計與更新商店，HubSpot 協助客戶在 Claude 中完成初始設定，Atlassian 協助 Claude 運用組織內的資訊。

通鑑判斷，變化最直接落在原本負責交代流程的人身上。以更新商店為例，使用者想要的是完成整間商店的調整，而不是逐項研究有哪些工具、每個工具該怎麼操作。這些例子呈現同一條路：由熟悉自家系統的服務提供者，把工作方法隨工具交給 Claude。對上班族來說，關鍵是能否用一個任務描述啟動整段工作，並在需要決定的地方接手。

另一項獨立功能 Tasks 已正式推出。過去工具呼叫要完成，Claude 才能繼續；現在伺服器能在背景處理耗時工作，Claude 可先做其他事，再接收結果。

通鑑認為，Tasks 改變的是等待工作的方式。以官方提出的 ZoomInfo 帳戶與聯絡人研究為例，這類調查可能涉及多個步驟，先前需要使用者發出好幾次提示；背景任務讓伺服器接手持續執行，Claude 不必停在原地等。它與 Skills over MCP 分工清楚：技能提供做事的方法，Tasks 提供把較長工作跑完的機制。兩者放在一起，才更接近上班族交辦一件完整工作的期待。

獨立功能 Elicitation 也已正式推出。伺服器可在工作中途用表單或連結請使用者輸入或確認；官方舉例，Supabase 在建立付費專案前確認費用，GitHub 在刪除儲存庫前要求輸入名稱。

通鑑判斷，這把人的決定放進了工作流程，而不是要求使用者全程盯著每一步。建立付費專案或刪除資料，都有明確的決策點；伺服器能在那一刻暫停、取得確認，再從原處繼續。使用者因此可以交辦多步驟工作，同時保留對花費與刪除動作的控制。對服務提供者而言，重要的設計問題也更具體：哪些步驟可以自動完成，哪些步驟一定要停下來問人。

File Uploads 則預計稍後推出，讓 Claude 把 PDF、試算表與圖片交給 MCP 伺服器處理，不必讓檔案內容經過對話的上下文視窗。

通鑑認為，檔案傳遞是這套工作方式的下一個關鍵環節。許多辦公任務從文件開始；若 Claude 只能把文字交給工具，處理文件便多了一道轉換。File Uploads 的方向是讓伺服器直接接收檔案，再配合技能指引與背景任務完成後續步驟。接下來值得看的具體事件，是這項功能正式開放後，服務提供者能否把上傳、處理與需要使用者確認的環節接成順暢的一次交辦。

通鑑怎麼看

通鑑認為，這次更新的主軸是讓「連上工具」變成「交辦工作」：技能教 Claude 怎麼做，Tasks 讓工作持續執行，Elicitation 在關鍵處請人決定。三項能力各自獨立，合在同一段工作流程時最有價值；服務提供者能否把自己的流程寫清楚，將直接影響使用者交辦工作的體驗。
