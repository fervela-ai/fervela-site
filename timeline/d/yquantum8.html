Chrome 公布量子安全 HTTPS 憑證計畫｜Google Chrome｜2 月 27 日 事件推薦

Chrome 要讓量子安全憑證變輕，才有機會讓整個網路換上它

Chrome 安全團隊公布量子安全 HTTPS 憑證計畫，並與合作夥伴在真實網路流量中測試。

這是什麼

HTTPS 憑證像網站出示的身分證，讓瀏覽器確認連到的是誰。Chrome 正研究以 Merkle Tree Certificates（MTC）取代傳統憑證的繁重簽章鏈，讓網站日後採用抗量子密碼時，仍能有效率地完成身分驗證。

三點帶走

  1. Chrome 研究以精簡的公開樹證明，減少抗量子憑證帶來的傳輸負擔。
  2. 真實流量實驗已展開，採用新憑證的連線目前仍有傳統憑證保障。
  3. 後續關鍵是實測效能、發證可靠性，以及新信任根政策能否具體執行。

重點與分析

Chrome 正與合作夥伴開發 MTC：憑證機構簽署一棵公開樹的摘要，網站再向瀏覽器提供自己列在樹上的精簡證明。官方表示，一個摘要可能涵蓋數百萬張憑證。

通鑑判斷，這項設計瞄準的卡關是憑證變大。傳統方式像每家店都帶著一整串蓋章文件，交給每位進門的顧客檢查；MTC 則像把店家名冊集中公告，每家店只需證明自己的名字在名冊上。抗量子密碼需要傳送更多資料，若沿用整串憑證，網站每次建立安全連線都得負擔較大的傳輸量。Chrome 選擇改造憑證的交付方式，讓密碼強度提升時，瀏覽器收到的身分證明仍維持精簡。

MTC 要求憑證列入公開樹，發證與公開紀錄綁在一起。Chrome 表示，這讓現有憑證透明度制度的安全特性成為發證流程的一部分。

通鑑認為，這改變了網站身分由誰監督、何時能被看見。MTC 把列入公開樹變成憑證成立的必要條件，就像證件核發時必須同步登記在可查的名冊。這也讓瀏覽器驗證身分所需的資料，不必再額外附上一套透明度證明。MTC 要求憑證列入公開樹，讓發證紀錄可供外部檢視。

Chrome 已與 Cloudflare（NET） 用真實網路流量研究 MTC 連線的效能與安全性。實驗期間，每條採用 MTC 的連線仍由傳統、受信任的憑證提供保障。

通鑑判斷，這項實驗最關鍵的是把新憑證放進日常連線，觀察它能否穩定簽發，以及瀏覽器實際會收到多少資料。憑證是開啟網站時就會碰到的基礎設施，小幅延遲若發生在大量連線上，也會影響使用感受。傳統憑證同時提供保障，讓 Chrome 能在真實流量中量測新做法，而不把使用者的連線安全押在研究結果上。接下來值得看的，是實測效能與發證可靠性是否支持擴大部署。

官方表示，部署規劃分階段進行：先研究可行性，再邀請符合條件的憑證透明度紀錄營運者參與，之後建立只支援 MTC 的量子安全信任根計畫。

通鑑認為，Chrome 選擇先借重現有憑證透明度營運者，是一條重用網路基礎設施經驗的路。這些營運者原本就維護供外界查核的紀錄，與 MTC 所需的公開樹有相近之處。Chrome 也規劃讓新的信任根計畫與既有計畫並行，網站和憑證機構便能逐步接入。近期 Cloudflare（NET） 展示的後量子 Matrix 原型著重連線時如何交換金鑰；Chrome 這次處理的是另一環：瀏覽器如何確認網站身分。兩者共同構成安全連線。

Chrome 也提出調整撤銷狀態通報、網域控制權驗證及憑證機構監督方式，並表示預期新制度會更重視持續、可由外部查核的監測。

通鑑判斷，真正難的部分不只是一張憑證能否變小，還包括憑證發錯、網站失去控制權或機構運作異常時，整套制度能否及時反應。Chrome 提出的方向像把定期體檢改成持續看儀表板：讓外界更常看見發證與營運狀態，也讓網域控制權的證明留下可查紀錄。這些仍是制度設計方向；接下來的具體關卡，是 Chrome 公布信任根政策後，如何訂出可執行的加入、監督與撤銷規則。

通鑑怎麼看

通鑑認為，Chrome 這次最有價值的選擇，是把量子安全憑證當成整套發證制度的改造，而非只替舊憑證換一種密碼。憑證夠輕，網站才容易普遍採用；發證紀錄可公開查核，瀏覽器才有基礎信任它。真實流量實驗將決定前者，後續政策將決定後者。
