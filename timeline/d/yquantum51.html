Google Cloud（GOOGL） 把後量子簽章帶進企業現有的金鑰管理流程

Google Cloud（GOOGL） 宣布，Cloud KMS 的後量子數位簽章與金鑰封裝功能已正式提供使用。

這是什麼

Cloud KMS 像替企業保管重要印章的保險箱：程式可請它用受管理的金鑰簽署資料。這次新增後量子演算法，讓企業能在既有服務中開始使用後量子簽章與金鑰封裝功能。

三點帶走

  1. Cloud KMS 已正式提供後量子數位簽章與金鑰封裝，兩者處理不同的安全環節。
  2. 大型資料可先在應用程式端算出小型指紋，再交由金鑰服務簽章。
  3. 企業的實際遷移要走通建立金鑰、應用程式簽署與接收端驗證。

重點與分析

官方宣布，Cloud KMS 正式提供 ML-DSA、SLH-DSA 數位簽章，以及 ML-KEM 金鑰封裝。應用程式可透過 Cloud KMS API 使用這些演算法。

通鑑判斷，關鍵改變是企業有了可接進既有系統的服務。數位簽章像文件上的防偽印章，讓接收者查驗文件是否遭改動、是否由對的金鑰簽出；兩者處理的是不同環節，不能只升級其中一項就以為整套流程都完成遷移。Cloud KMS 同時提供這兩類功能，讓使用它的團隊可以從盤點簽章與金鑰交換的用途開始，逐一安排改動。

官方指出，大型檔案送進安全設備簽章，會遇到傳輸量與處理能力的限制。Cloud KMS 因此支援預先雜湊及 external-µ 等作法。

這解開的是大型資料難以直接交給金鑰服務處理的卡關。雜湊可想成先替整份文件算出一枚固定大小的指紋，再把指紋送去簽章；官方表示，這枚指紋約為 32 位元組。檔案再大，送往保管私密金鑰的系統時也只需傳送小量資料。難處在於縮小傳輸內容後，簽章仍須能由相應的驗證方式檢查。官方說明，external-µ 可配合純 ML-DSA 的驗證方式，並把公開金鑰與訊息摘要連結，防止攻擊者操弄摘要，使其能在另一把金鑰下通過驗證。

官方列出多種 ML-DSA 與 SLH-DSA 選項，涵蓋不同安全等級與簽署方式；其中 ML-DSA 提供純簽章及 external-µ 版本。

通鑑認為，這讓遷移從選用一個新演算法，變成依用途選擇簽署方式。不同系統要簽的可能是短訊息，也可能是龐大檔案；驗證端能接受的格式也得納入考量。Cloud KMS 提供多個選項，團隊便能把資料大小、驗證流程與所需安全等級放在同一張表上比較。這條路與只替網路連線加入後量子保護的進展不同：數位簽章有助於查驗資料的完整性與真實性。

官方表示，開發者可沿用 Cloud KMS 建立、管理及使用金鑰的能力，並透過 API 將後量子演算法接入應用程式。

接下來決定這項功能能否用起來的具體事件，是企業能否讓現有應用程式完成一次簽署與驗證流程。建立金鑰只是起點；程式還要選對簽章方式，把結果交給接收端，並確認接收端能驗證。通鑑判斷，沿用 Cloud KMS 的管理方式可減少另建金鑰管理流程的工作，但應用程式與驗證端仍須一起調整。對負責遷移的團隊，最有用的第一步是選定一項現有簽章用途，確認資料大小、所用方式及驗證端，再走通完整流程。

通鑑怎麼看

通鑑認為，這次進展的價值是把後量子密碼從演算法選項，推進到企業可著手整合的金鑰服務。尤其大型資料的簽章流程有了明確作法，企業可以從一項既有用途開始，檢查簽署、金鑰管理與驗證能否接上。
