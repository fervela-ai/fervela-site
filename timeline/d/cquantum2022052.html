Amazon Braket Hybrid Jobs 支援內嵌模擬器（embedded simulators）｜Amazon Web Services（AWS）｜5 月 5 日 事件延伸

Amazon（AMZN） Braket 混合工作新增內嵌模擬器，可用 GPU 加速量子電路模擬

AWS 官方部落格表示，Braket 的混合工作（Hybrid Jobs）現在可以把模擬器直接放進演算法程式碼裡執行，其中一項是以 NVIDIA（NVDA） cuQuantum 加速的 PennyLane GPU 模擬器。

這是什麼

Amazon（AMZN） Braket 是 AWS 的量子運算雲端服務；Hybrid Jobs 是它讓「量子加傳統」混合演算法在雲端自動排程執行的功能。這次新增的是『內嵌模擬器』：模擬器不再是遠端的獨立裝置，而是和演算法程式碼放在同一台工作實例上跑。

三點帶走

  1. Braket Hybrid Jobs 新增內嵌模擬器，模擬與演算法程式碼在同一個工作實例上執行。
  2. 官方範例顯示 20 個量子位元時 GPU 比 CPU 快約 20 倍、費用約省一半，但這只是特定範例。
  3. 小工作與多實例平行時成本結構不同，官方也提醒要先評估是否值得。

重點與分析

官方表示，這項新功能讓使用者在 Hybrid Jobs 中，使用與演算法程式碼嵌在一起的模擬器；其中一個是由 NVIDIA（NVDA） cuQuantum 函式庫加速的 PennyLane Lightning GPU 模擬器。

以前 Hybrid Jobs 可選擇的裝置是量子處理器（QPU）或 Braket 的隨選模擬器（SV1、DM1、TN1）。現在多了第三種：模擬在工作實例上直接執行。這個改變對研究者的意義在於測試與除錯：官方指出，現階段的量子處理器在尺寸與相干性上有限，模擬器不只用來除錯，也用來在理想條件或可控雜訊下研究新方法。需要注意的是，這是模擬，不是在真實量子硬體上跑，結果不能直接當作硬體表現。

官方表示，把模擬放在演算法旁邊可以降低與遠端裝置通訊的延遲，這對量子位元數低（通常到約 20 至 25 個）的工作是瓶頸；內嵌模擬器也支援伴隨微分（adjoint differentiation）等進階模擬策略。

這段說明了設計動機：量子位元少的工作，每次呼叫遠端裝置的來回時間可能比計算本身還久。伴隨微分是一種更有效率地計算梯度（模型參數該往哪個方向調整）的方法，對變分量子演算法這類需要大量重複調整參數的工作特別有用。官方另外提到，透過自帶容器（BYOC）功能，使用者也可以嘗試其他開源模擬函式庫，所以內嵌模擬器是一個開放的架構，不只限於 PennyLane。

官方表示，以 20 個量子位元的量子機器學習範例（Sonar 資料集，208 筆資料、60 個特徵）為例，GPU 每個訓練回合約 1 分鐘、CPU 約 20 分鐘，費用分別為 0.06375 美元與 0.1536 美元，GPU 快約 20 倍且省約 50% 費用。

這是官方自己挑的範例，條件很具體：20 個量子位元、特定資料集、特定實例（CPU 用 ml.m5.2xlarge，GPU 用 ml.p3.2xlarge）。單位時間 GPU 實例比較貴（每分鐘 0.06375 美元對 0.00768 美元），但因為跑得快，總成本反而較低。這個結論只適用於 GPU 確實能發揮的規模；官方也坦白提醒，像『Hello, world』這樣的小工作不建議用 Hybrid Jobs，因為開機要幾分鐘，比演算法本身還久。換成別的電路大小或模型，倍數不一定相同。

官方表示，使用者可以用 SageMaker 分散式資料平行函式庫，把損失計算分到多張 GPU，需選 ml.p3.16xlarge（8 張 GPU）並修改演算法程式碼；使用多個實例時，計費時間是執行時間乘以實例數。

資料平行的概念是：每筆資料的損失彼此獨立，可以同時算，再取平均。官方強調必須依開發指南修改演算法程式碼，否則啟用資料平行選項也不會得到正確結果。這部分的重點是成本提醒：四個實例同時跑，計費就是四倍的時間，所以加速不等於省錢。對想用這項功能的人來說，值得先用小規模實驗確認加速比，再決定要開幾個實例。

通鑑怎麼看

通鑑認為，這則新聞的意義是量子雲端服務開始把『高階模擬』當成正式的工作選項，並直接接上 GPU 生態。它反映的是量子演算法研究目前仍大量依賴模擬器；而官方給的倍數與成本，是在特定範例下的結果，採用前仍需用自己的工作量重新量測。
