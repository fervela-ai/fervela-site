Windows 公布後量子程式碼簽章轉換安排｜Microsoft｜8 月 20 日 事件入門

Windows 換簽章，真正的考驗是軟體能不能跟著換

Microsoft（MSFT） 公布 Windows 程式碼簽章的轉換安排，提醒軟體開發商與企業管理員檢查應用程式如何判斷檔案可信。

這是什麼

程式碼簽章像軟體的防偽封條，供 Windows 判斷簽章是否可信。Microsoft（MSFT） 正更換簽章憑證、提高演算法強度，並準備轉向後量子簽章；應用程式若只認得舊封條的樣式，就可能把 Windows 認可的檔案擋下。

三點帶走

  1. Windows 認可的檔案，仍可能被只認舊憑證或固定演算法的應用程式擋下。
  2. 企業應確認關鍵軟體如何驗證簽章，並向供應商索取新憑證與較強簽章的測試結果。
  3. 後量子簽章轉換的長期關鍵，是讓應用程式能隨憑證和演算法更換而持續運作。

重點與分析

Microsoft（MSFT） 表示，Windows 正更換用於簽章的憑證機構。把舊憑證名稱、發行者或指紋寫死在程式裡的應用程式，可能在轉換時失效。

通鑑判斷，第一道卡關不是新簽章有多複雜，而是既有軟體把「辨認某張憑證」誤當成「確認檔案可信」。這像大樓換了合格的門禁卡，警衛卻只肯放行舊卡面的人。憑證原本就會更換；如果程式只認舊資料，即使 Windows 已確認新簽章有效，也可能拒絕檔案。企業該盤點的因此不只是作業系統版本，還包括會檢查 Windows 檔案簽章的管理工具與關鍵應用程式。

Microsoft（MSFT） 表示，Windows 簽章將朝 RSA-3072 與 SHA-384 等更強的組合轉換。要求簽章只能使用固定演算法的程式，也可能因此出現相容性問題。

這項變動會碰到另一種較隱蔽的假設：程式把目前常見的簽章組合當成永遠不變的規格。Microsoft（MSFT） 列出的風險包括強制要求特定演算法，以及自行解析簽章或憑證鏈。通鑑認為，改用更強的組合只是讓問題浮現；即使這次逐一加入新組合，下次再換仍得重修。較穩定的做法是讓 Windows 支援的信任介面判斷簽章是否可信，讓應用程式依判斷結果行事。

Microsoft（MSFT） 表示，其測試已發現部分應用程式在簽章憑證或演算法變更後失效；其中包括要求不同檔案的憑證鏈完全相同，以及使用未更新的私人信任清單。

受影響的不只寫程式的人。企業管理員可能最先看到的是應用程式拒絕 Windows 認定可信的檔案，或應用程式與 Windows 對同一個檔案給出不同判斷。通鑑判斷，企業採購與維運現在需要問供應商更具體的問題：產品是否使用 Windows 支援的信任介面、是否固定綁定 Microsoft（MSFT） 憑證、是否測過新憑證與較強的簽章，以及私人信任清單如何更新。這些回答比一句「支援新版 Windows」更能指出實際故障點。

Microsoft（MSFT） 表示，Windows 簽章將轉向預設採用後量子簽章，同時考慮較舊平台與舊系統；未來也可能使用新演算法或混合式簽章。

Microsoft（MSFT） 正準備讓 Windows 程式碼簽章轉向後量子密碼技術。Windows 簽章轉向預設採用後量子技術時，Microsoft 表示會考慮較舊平台與舊系統。通鑑認為，這次安排的關鍵在於「能換」：Microsoft 已把較舊系統列入考量，也指出往後可能需要迅速調整簽章方式。接下來能否順利轉換，要看供應商測試新簽章後修正多少相容性問題，而不只是看 Windows 換上哪一種演算法。

通鑑怎麼看

通鑑認為，這是一次檢查軟體信任設計的機會。Windows 可以更換憑證與演算法，但應用程式若自行規定可信簽章必須長什麼樣，升級就會變成故障。開發商應把判斷交給 Windows 支援的介面；企業則應要求關鍵軟體供應商提出測試結果與更新安排。
