Claude Code Security 把找漏洞與修補建議放進同一套流程

Anthropic 推出 Claude Code Security，讓團隊在網頁版 Claude Code 檢查程式漏洞、審查修補建議；目前僅提供有限的研究測試版。

這是什麼

這是整合在網頁版 Claude Code 的資安功能。它閱讀程式各部分如何互動、資料如何流動，找出可能的漏洞並提出修補建議，最後由開發者決定是否採用。

三點帶走

  1. 它檢查程式脈絡，目標是找出規則式掃描較易遺漏的複雜漏洞。
  2. 發現與補丁都要由人審查；修改不會自動套用。
  3. 目前是有限研究測試，官方研究成果不等於產品在所有專案的表現。

重點與分析

傳統規則式工具主要比對已知漏洞樣式；Claude Code Security 則檢查程式脈絡，尋找業務邏輯或存取權限等較複雜的問題。

通鑑判斷，這項功能的價值在於補上既有掃描工具較難處理的情境：一段程式單看可能沒問題，與其他功能串起來卻可能讓不該取得資料的人通過。這也意味著檢查結果需要懂系統的人判讀。工具能提出疑點，是否真能被利用、修補後會不會影響原有功能，仍須結合實際運作情境確認。

每項發現會經過多階段驗證，系統會重新檢查，嘗試證實或推翻自己的判斷、過濾誤報；發現會被賦予嚴重程度，Claude 也為每項發現提供信心評級；通過驗證的發現出現在儀表板，團隊可在那裡檢視並檢查建議補丁。

通鑑判斷，資安團隊面對的難題不只是找到問題，還包括從大量警示中決定先處理什麼。嚴重程度有助於排順序，信心評級則提醒審查者留意判斷的不確定性。不過，這些標示不能代替驗證：尤其是牽涉業務規則的漏洞，光看程式碼可能不足以判定實際風險。

建議補丁須由人審核；開發者核准前，Claude Code Security 不會套用任何修改。

通鑑判斷，把核准權留給開發者，是這套流程能否用於實際專案的關鍵。修補一處權限問題，可能同時改變正常使用者的操作路徑；看似合理的補丁也可能沒有堵住真正的漏洞。團隊仍需檢查修改內容，並依自己的測試與發布流程確認結果。

官方宣稱，團隊使用 Claude Opus 4.6，在正式使用中的開源程式庫找到超過 500 個漏洞；目前仍在與維護者確認並依負責任揭露流程處理。

通鑑判斷，這個成果顯示模型值得投入資安研究，但不能直接當成 Claude Code Security 在一般企業專案中的檢出率。這是 Anthropic 團隊使用指定模型檢查開源程式庫的結果，而且官方表示後續確認與揭露仍在進行。要評估產品成效，還得看實際使用時找到多少可確認、值得修補的問題。

目前僅向企業版與團隊版客戶提供有限研究測試；開源專案維護者可申請免費的加速存取。

通鑑判斷，現在更適合把它視為需要共同測試的工具，而非已完成驗證的通用服務。有限開放讓參與團隊有機會檢查它在自身程式庫的表現，也讓 Anthropic 收集回饋。考慮申請的團隊，應先準備好由誰審查發現、如何確認漏洞，以及如何驗收補丁。

通鑑怎麼看

Claude Code Security 把 AI 找漏洞、篩選發現與提出補丁接成一條工作流程，最值得觀察的是它能否減少資安人員核查無效警示的時間。官方展示了研究成果，但產品仍處有限測試；真正的考驗，是不同團隊能否穩定確認其發現，並安全地採用修補建議。
