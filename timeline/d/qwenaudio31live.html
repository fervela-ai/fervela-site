Qwen-Audio-3.1-Live 讓語音助理邊辦事、邊交代進度

Alibaba Cloud 在官方文件中介紹這款即時語音模型：工作交給應用程式或後端模型處理時，它仍能與使用者持續對話。

這是什麼

qwen-audio-3.1-live 是 Alibaba Cloud 的語音互動模型。可以把它想成接待窗口：複雜工作交給後方處理，窗口仍能聽使用者說話，並用語音回報進度與結果。

三點帶走

  1. 全雙工語音讓模型在任務處理期間仍可與使用者交談、回報進度。
  2. 任務可由應用程式或指定後端模型處理，兩種模式都能連接商業工具。
  3. 費用按連線時長計算，靜音與閒置也計費；後端模型費用另計。

重點與分析

官方表示，模型支援即時全雙工語音對話；應用程式或後端模型處理任務時，語音模型可以繼續與使用者互動，並說明進度和結果。

「全雙工」像通電話：雙方都能持續說話與聽話，不必等一方完成整段發言才換人。通鑑判斷，這項設計要解的卡關是語音助理一接到較複雜的工作，使用者便失去互動窗口。把說話與辦事分開，等待過程就有機會變成可追問、可接收進度的對話。對需要一邊確認需求、一邊處理工作的服務來說，這比只在最後念出答案更貼近真人交談。

官方表示，Client 模式由應用程式處理任務；Responses 模式則由 Model Studio 呼叫指定的後端模型。兩種模式都支援透過函式呼叫連接商業工具。

兩種模式的差別在於工作交給誰：一種由原本的應用程式接手，另一種由 Model Studio 呼叫後端模型。通鑑認為，這讓語音介面有兩條接入路徑。已有工作流程的服務，可以由自己的程式處理任務；需要後端模型參與的服務，則可選另一種模式。「函式呼叫」好比讓接待窗口把工作單交給指定工具，語音對話才有機會接上實際業務，而非停在口頭回答。

官方文件列出的輸入與輸出都包含文字、音訊，並支援函式呼叫；內建網頁搜尋、結構化輸出、批次推論及模型調校則未支援。

通鑑判斷，這份能力清單把產品定位說得很清楚：它主要負責持續的語音往返，其他工作要依靠應用程式、工具或後端模型安排。想像接待窗口能聽、能說、能轉交工作，但不會因此自帶每一種辦事能力。對準備導入的團隊，關鍵工作是先列出對話中需要查什麼、處理什麼，再確認各項工作由哪個工具承接。這會直接影響使用者聽到進度後，能否接著完成事情。

官方表示，費用依連線秒數計算，靜音和閒置時間也計費；每次連線至少計費 3 秒。官方列出的新加坡價格為每秒 0.000710 美元，北京為每秒 0.000471 美元，後端模型另計。

通鑑認為，計費單位是這款模型能否用於日常服務的關鍵。傳統文字互動容易把成本想成送出多少內容；這裡只要連線持續，等待使用者開口、保持安靜或等任務完成，都會累積語音費用。若使用 Responses 模式呼叫後端模型，還要加上後端實際使用詞元的費用。因此，評估成本時應看完整對話從連線到結束的時長，並把後端費用分開計算；只看說了多少話，會漏掉等待期間的支出。

通鑑怎麼看

通鑑認為，Qwen-Audio-3.1-Live 的重點是把「持續交談」和「處理任務」拆開，讓語音助理在工作進行中仍保有互動窗口。這條路線能否實用，取決於工具能否接好業務流程，以及連線等待時間帶來的成本是否合適。
