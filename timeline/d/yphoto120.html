Meta 推出 WebXR 的 Web Launch｜Meta｜11 月 29 日 事件推薦

Meta（META） 用 Web Launch 接上網頁與頭戴裝置之間的最後一步

Meta（META） 在開發者文章中介紹 Web Launch，示範使用者如何從手機上的網頁進入 Quest 頭戴裝置，繼續觀看同一個 WebXR 體驗。

這是什麼

WebXR 是讓網站呈現虛擬實境內容的技術，可以想成先在手機看房屋照片，再戴上頭戴裝置走進房子。Web Launch 負責把目前網址送到裝置上，並在裝置內開啟網站，讓這兩步接得起來。

三點帶走

  1. Web Launch 讓使用者把手機上正在看的 WebXR 網站網址送到 Quest 頭戴裝置，並在裝置內開啟網站。
  2. 暫時無法戴上裝置時，使用者可以先儲存網站，稍後再找回。
  3. 網站在頭戴裝置內開啟後，使用者仍可能需要再操作一次，才會進入完整的虛擬實境。

重點與分析

整合 Web Launch 的網站可讓使用者選擇 Quest 裝置，將目前網址送到頭戴裝置，並在裝置內的 Quest Browser 開啟。

通鑑判斷，這解開的是進入體驗前的操作卡關：使用者已在手機找到想看的內容，戴上頭戴裝置後若還得重新搜尋，很容易在搜尋與辨認網站的過程中停下來。Web Launch 讓網站接續原本那個網址，開發者也能把入口放在使用者已經接觸內容的位置。它改善的是從發現內容到打開內容的路徑，而不是替網站製作虛擬實境內容。

使用者也可以先儲存網站，稍後在登入的頭戴裝置或 Quest 手機應用程式中，從個人資料的已儲存項目找到它。

通鑑認為，稍後開啟比立即開啟更貼近日常使用：在通勤或工作空檔滑到一個立體展示時，頭戴裝置往往不在手邊。儲存功能讓感興趣的當下與實際戴上裝置的時候分開，也讓使用者有地方找回內容。對網站經營者來說，這改變了入口的設計：手機頁面可以先爭取使用者留下體驗，等他準備好時再進入頭戴裝置。

Meta（META） 以 Matterport 的立體空間導覽示範：使用者從手機點選進入虛擬實境的圖示，選好裝置後，仍須在頭戴裝置內點選進入虛擬實境，才會開始以第一人稱探索。

通鑑判斷，這個例子把 Web Launch 的角色說得很清楚：它先把人帶到正確網站，網站再讓人進入完整的虛擬實境。兩次操作對應兩個選擇，使用者可以先在頭戴裝置內確認內容，再決定是否走進立體空間。像 Matterport 這類展示實際場所的服務，從平面畫面切到第一人稱視角，觀看方式才真正改變；Web Launch 負責讓這個切換更容易開始。

開發者可使用 Web Launch 提供的網頁入口，自行安排網站上觸發開啟流程的位置與方式。Meta（META） 也提到 Quest Browser 支援透視畫面、場景理解與空間錨點等 WebXR 功能。

通鑑認為，Web Launch 選擇從既有網站加入入口，讓開發者能依內容安排使用者何時進入頭戴裝置：看房屋導覽的人可能先在手機挑選地點，進入立體空間後才仔細觀看。Quest Browser 的能力則決定網站進入裝置後能呈現什麼。接下來最有意義的觀察，是使用者點擊網站入口後，有多少人真的在頭戴裝置內打開網站、進一步進入完整體驗。

通鑑怎麼看

通鑑認為，Web Launch 的價值在於讓手機上的發現變成頭戴裝置裡可接續的體驗。它把網址傳送、稍後儲存與裝置內開啟串成一條路；Matterport 的示範也顯示，真正進入虛擬實境仍由網站內的操作完成。這條路能否帶來更多實際觀看，關鍵在使用者是否願意走完最後一步。
