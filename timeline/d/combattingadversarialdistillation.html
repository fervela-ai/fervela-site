OpenAI 把防蒸餾的重心放在保護模型的解題過程

OpenAI 在技術說明中交代如何防範對抗性蒸餾，以及為何模型的內部推理成為防護重點。

這是什麼

蒸餾像學生讀老師的解答來學解題；對抗性蒸餾則是未經授權，大量取得模型輸出來訓練另一個模型。OpenAI 關切的是：新模型可能學到資安等能力，卻沒有原模型的安全限制。

三點帶走

  1. 對抗性蒸餾的風險，是能力被複製後可能脫離原模型的安全限制。
  2. 完整內部推理比最終答案更可能教會另一個模型解題方法。
  3. 防護涵蓋模型回覆、工具參數、API 對話邊界與跨帳號行動。

重點與分析

OpenAI 表示，模型的答案、推理和答案評選都能成為另一個模型的學習資料。若有人擷取資安能力，再用較少限制的模型提供攻擊協助，原模型的防護就可能被繞過。

通鑑判斷，這件事的核心是能力和安全限制可以分開轉移。防守者用 AI 找軟體漏洞，攻擊者也可能學會利用同類漏洞；生物研究同樣有這種雙重用途。只檢查原模型會不會拒絕危險提問，守不住另一個從它身上學到本事的模型。因此防護必須往前移到訓練資料的取得環節：哪些輸出容易教會別人關鍵能力、哪些擷取行為值得攔截，都要一起處理。

OpenAI 特別保護模型的內部推理。它像解題草稿，比交給使用者的最終答案更完整；官方研究發現，取得完整推理的學生模型，在部分資安測試條件下表現較好。

通鑑認為，保護草稿比只保護答案更切中難題：答案告訴學生做出了什麼，草稿還可能教它如何一步步做出來。官方研究從相同的預訓練學生模型出發，比較學習完整推理與推理摘要的結果。完成監督式微調後，前者通常較好；再經過一輪輕量強化學習，前者在圖示兩項測試的最高推理額度下仍較好，較低額度則是學摘要的學生較好。差異指出完整推理有額外價值，也說明保護重點不能只看最後顯示的文字。

OpenAI 的單次請求防護包括訓練模型拒絕洩露內部推理、檢查輸入與輸出的分類器，以及 API 限制。輸出檢查也涵蓋模型交給工具的參數。

通鑑判斷，工具參數是容易被忽略的出口：模型即使沒有在回覆中顯示推理，仍可能把內容塞進呼叫工具時傳送的資料。這讓防護從檢查使用者看見的答案，延伸到檢查系統實際送出的內容。API 也把 GPT-6.2 Astra 與 GPT-6.2 Sol 的受保護推理綁定產生它的對話歷史；較早的訊息若被改寫，後續推理便會被丟棄。這些安排針對的是跨對話搬運推理的手法，不能單靠要求模型拒答來完成。

官方宣稱，在會依系統回應調整手法的內部黑箱測試中，擷取先前請求推理的平均成功率，從原有防護的 GPT-6 Astra 的 54.0%，降到更新防護後 GPT-6.2 Astra 的 0.2%。

通鑑認為，這是最值得持續追蹤的數字：相同類型的擷取測試，原本約每兩次成功一次，更新後約每五百次成功一次。黑箱測試讓攻擊者只看得到外部使用者能看到的資訊，自動化測試者還會依防護反應改變策略，因此比反覆使用固定題目更貼近攻防過程。下一步要看同類測試在後續防護更新後如何變化；成功率若再次升高，就表示攻擊手法已找到新的出口。

OpenAI 表示，它會從請求與帳號訊號調查有組織的擷取行為；確認違規後，依政策處理相關帳號網路，並與其他模型業者分享入侵指標。

通鑑判斷，這把防線從單一提問擴大到整場行動。一次請求可能看似普通，許多帳號協同取得能力時，整體模式才會顯露；調查發現的攻擊又能回頭成為訓練與測試案例。分享入侵指標則讓其他業者能檢查自己的服務是否遇到相關行為。對抗性蒸餾牽涉跨帳號、跨服務的擷取，單靠提高某個模型的拒答能力，處理不了整個流程。

通鑑怎麼看

通鑑認為，OpenAI 這次最有價值的進展，是把內部推理當成需要保護的能力來源，同時封住回覆、工具參數與跨對話重用的出口。資安能力可以從正當任務的解題過程轉移，防護因此必須涵蓋單次請求與有組織的擷取行動。
