MiniMax H3 開源影片模型，但完整製作流程仍依賴官方服務

MiniMax 發表 H3，主打讓文字、圖片、影片與音訊共同引導短片生成。

這是什麼

MiniMax H3 是可同時生成影片與立體聲音訊的通用影片模型。官方釋出部分模型權重，也提供 API 使用包含輸入處理與高解析度生成的官方流程。

三點帶走

  1. H3 支援多種素材引導短片生成，並可同時產生立體聲音訊。
  2. 最高解析度需要重新生成；輸出規格不代表每次成品都符合需求。
  3. 開源權重未包含官方的輸入處理系統，使用方式會影響實作工作量。

重點與分析

官方宣稱 H3 可生成最長 15 秒的影片與 32 kHz 立體聲音訊；透過 H3-Regenerate-2K，解析度可達 2K。官方宣稱對話穩定支援 11 種語言。

通鑑判斷：畫面、聲音與對話能在同一套系統中產生，對需要快速做出短版廣告或產品示意片的人有吸引力。不過，最高解析度要經過先生成影片、再重新生成的流程；這些規格也只說明可輸出的範圍，無法據此判定每次生成的畫面、聲音和對話都能符合要求。實際採用前，仍要用自己的腳本與語言測試成品。

H3 可用首尾影格指定畫面，也可混合圖片、參考影片與音訊引導生成；音訊不能單獨作為參考輸入，必須搭配圖片或影片。

通鑑判斷：這些輸入方式讓使用者能指定開頭、結尾或參考素材，比只輸入一句文字更容易表達想要的內容。值得觀察的是，模型能否在生成過程中維持人物、商品與場景的一致性。音訊不能單獨輸入也是明確限制：若手上只有旁白或配樂，仍須先準備視覺素材，才能使用對應的參考模式。

開源版提供可輸出 768p 影片的 H3-Base；負責理解並整理複雜輸入的 H3-Context-IR 未納入開源釋出。官方提供 API 重現官方工作流程。

通鑑判斷：開源權重讓開發者有機會自行部署生成模型，但這不等於取得完整的官方流程。官方說明把輸入處理列為影響成品品質的重要環節，而該環節依賴託管服務。想自行部署的團隊需要評估能否建立替代的輸入處理方式，並比較結果；想沿用官方流程的團隊，則需要把 API 納入實際作業安排。

官方表示，提交的文字、圖片、影片及處理後的提示內容會經過自動審查；疑似違法、色情或侵害第三方權利的內容可能被阻擋，審查也可能出錯。

通鑑判斷：拿 H3 製作對外內容時，不能把系統允許生成視為已取得素材使用權，也不能把遭阻擋直接等同於內容違規。官方承認過濾可能誤判或漏判，並指出使用者仍須遵守授權條款。若工作涉及客戶提供的照片、影片或品牌素材，值得事先確認使用權與人工審稿責任，避免把內容審查當成最終把關。

通鑑怎麼看

通鑑判斷：H3 的看點是把多種參考素材、影片與立體聲生成放進同一套流程；開源的範圍則需要看清楚。先用自己的素材測試成品，再決定採用官方 API 或自行部署，會比只看最高輸出規格更有助於評估它能否進入工作流程。
