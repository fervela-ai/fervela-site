AlphaProof Code 把安全證明推進到裝置上實際執行的程式

Google DeepMind 發表 AlphaProof Code，以 Signal 的加密程式示範 AI 如何協助完成數學驗證。

這是什麼

形式驗證像替程式寫一份精確的安全契約，再用數學檢查它是否履約。AlphaProof Code 讓人類專家訂定並審核契約，由 AI 代理撰寫證明，最後交給 Lean 自動檢查。

三點帶走

  1. 安全規格由人類專家逐條審核，AI 負責完成證明。
  2. 驗證深入實際執行的程式，縮小設計與實作之間的落差。
  3. 已知漏洞測試與正開源的形式驗證成果，提供後續檢查和擴展的起點。

重點與分析

研究人員先與模型把 Signal 的安全目標寫成數學規格，每一條都經人類專家審核；之後才由 Gemini Carbon 驅動的 AI 代理完成證明。

通鑑認為，這個分工抓到了形式驗證最難交給 AI 的一關：先說清楚究竟要證明什麼。程式即使完全符合一份規格，若規格漏掉重要的安全情境，證明也無法替使用者補上保障。讓專家逐條審核安全目標，等於由人決定安全契約的內容，再讓 AI 處理耗時的證明工作。這也說明 AlphaProof Code 的價值不只是讓 AI 寫得更快，而是把專家的時間集中在需要判斷的地方。

DeepMind 表示，這次驗證從協定設計深入到裝置執行的程式碼，檢查核心加密程式是否符合指定的安全性質；官方宣稱整個流程花了四週，過去專家團隊通常需要數年。

協定設計像建築圖，實際程式則是蓋好的房子；圖畫得安全，施工細節仍可能出錯。通鑑判斷，這次進展的關鍵是把設計與實作之間的落差納入證明範圍，並涵蓋裝置暫時遭入侵前後的訊息保護。這比只檢查設計困難，因為證明必須對上真正執行的程式。時間若能從以年計縮到以週計，原本難以投入如此密集審查的系統，也較有機會採用這種方法。

官方宣稱，AI 代理產生超過六百萬行 Lean 證明內容；系統另標出約百分之一的程式碼，交由人類再次查看，所有證明均由 Lean 檢查。

Lean 可以想成一位嚴格的數學閱卷者：AI 寫出解題過程，它逐步檢查推導是否成立。通鑑認為，這種安排讓大量產出具有可檢查的依據，也改變了專家的工作位置。人不必逐行讀完龐大的證明內容，而能把注意力放在系統標出的疑點與安全規格本身。接下來最值得觀察的，是換到其他大型程式時，需要專家複查的範圍能否維持在可負擔的程度。

DeepMind 把先前已修復的兩個真實漏洞重新放進隔離的 Signal 程式版本；官方表示，系統在兩次測試中都產生經機器檢查的證明，指出有漏洞的版本不安全。

證明正確版本符合規格，和辨認有問題的版本，是兩種不同能力。這項測試刻意放回已知漏洞，讓系統面對確定有錯的程式，而不只是完成原先安排的證明題目。通鑑判斷，這使成果更接近安全團隊的實際需求：當程式改動引入問題，驗證流程必須能指出保護在哪裡失效。對後續應用而言，持續修改中的程式能否反覆接受這種檢查，會比一次完成證明更有決定性。

通鑑怎麼看

通鑑認為，AlphaProof Code 最有分量的突破，是讓人類訂定安全標準、AI 承擔大量證明工作，並由 Lean 檢查每一份證明。它把過去昂貴且耗時的嚴格驗證，推向更貼近實際程式的範圍。DeepMind 正將這次的形式驗證成果開源；其他團隊能否據此重做並擴展到不同系統，是下一步的看點。
