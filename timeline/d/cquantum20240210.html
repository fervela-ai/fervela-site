Qiskit 1.0 上線：新增 V2 原語與 OpenQASM 3 匯入，也清掉一批舊介面

Qiskit 官方 GitHub 釋出頁公布 1.0.0 版變更清單，重點是新增 V2 原語（primitives）與原生 OpenQASM 3 匯入器，同時移除許多已棄用的功能。

這是什麼

Qiskit 是開源的量子程式開發套件，開發者用它撰寫量子電路並送到模擬器或 IBM 的量子硬體。1.0.0 是它的第一個穩定主版本。這份釋出頁是原始的變更清單（changelog），逐條列出 Qiskit 專案的合併請求，並指向官方發行說明。

三點帶走

  1. 官方釋出頁顯示 Qiskit 1.0.0 於 2 月 15 日發布，新增 V2 原語基底類別與原生 OpenQASM 3 匯入器
  2. 官方清單顯示移除 execute()、algorithms、opflow、IBMQ 相關功能與 Aer 匯入等舊介面
  3. 清單未附效能數字，影響需對照官方發行說明評估

重點與分析

官方釋出頁表示，1.0.0 版新增 EstimatorV2 與 SamplerV2 的基底類別（BaseEstimatorV2、BaseSamplerV2），以及 EstimatorV2 的參考實作和以狀態向量為基礎的 SamplerV2，並移除原語基底類別上的驗證方法。

原語（primitives）是 Qiskit 把『取樣』與『期望值估計』包成標準介面的方式。V2 版本代表接口改版，開發者的程式碼需要配合。清單只列出了新增項目，沒有說明 V2 與舊版的行為差異，具體差異要看官方發行說明連結。

官方釋出頁表示，新增原生 OpenQASM 3 匯入器，並支援 OpenQASM 3 的 switch 語法；另新增 Python 3.12 支援、transpiler 的 num_processes 參數，以及以 Rust 重寫的 two_qubit_decompose.num_basis_gates。

OpenQASM 3 是量子電路的文字交換格式，原生匯入器讓 Qiskit 不再需要外部套件來讀取；Rust 重寫則反映專案把效能關鍵部分搬到 Rust 的方向。但清單沒有附效能數字，這些項目只能確認已被合併，無法從此判斷速度提升多少。

官方釋出頁的『Removed』清單很長，包括移除 execute() 函式、qiskit.algorithms 模組、opflow 模組與 QuantumInstance、qiskit.extensions、qiskit.tools、舊版 IBMQ 相關功能，以及 Aer 的匯入（qiskit.providers.aer）。

與以往小版本逐步累積棄用相比，1.0 一次性清除了多個舊 API，這代表舊程式可能無法直接在 1.0 上執行。清單也寫明將 qiskit 元套件改為取代 qiskit-terra，這讓安裝方式有所改變。這是使用者最需要注意的部分，而不是新增功能。

官方釋出頁表示，本版由 mtreinish 在 2 月 15 日發布，並指向 docs.quantum.ibm.com 的發行說明；變更清單另有 Fixed 區塊，修正了 QPY、MPL 繪圖、屏障（barrier）處理等問題。

這個頁面是工程師導向的原始清單，沒有針對讀者的敘事，也沒有統計新增了幾項功能。想理解對自己專案的影響，應先看發行說明，再依 Removed 清單檢查程式中是否用到已移除的介面。

通鑑怎麼看

通鑑認為，Qiskit 1.0 的意義在於把介面整理成穩定主版本，代價是移除大量舊介面；對使用者而言，遷移成本比新增功能更值得關注。
