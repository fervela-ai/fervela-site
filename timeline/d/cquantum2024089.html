IBM Qiskit SDK v1.2 發布：電路基礎架構改寫為 Rust，轉譯與合成大幅加速｜IBM Quantum｜8 月 21 日 事件進階

Qiskit v1.2 發布：Rust 化帶來數十到數百倍合成加速

IBM 的技術發布摘要說明 v1.2 的效能改進、轉譯器新功能與即將到來的 v1.3 重大變更。

這是什麼

Qiskit 是 IBM 主導的開源量子運算軟體開發套件。轉譯（transpile）指把使用者寫的量子電路，改寫成特定量子硬體能執行的形式並盡量減少閘數。v1.2 的重點是效能與品質，而不是新硬體功能。

三點帶走

  1. Qiskit v1.2 把電路基礎架構改寫成 Rust。
  2. IBM 官方宣稱雙量子位元合成近 100 倍、Clifford 合成近 500 倍加速（對比 v1.0.2）。
  3. v1.3 將預設優化等級改為 2，並停止支援 Python 3.8。

重點與分析

IBM 官方表示，v1.2 把所有電路基礎架構（例如閘與運算）改以 Rust 實作，使電路建構與操作加速；合成函式庫的許多部分現在直接用 Rust 建電路。

Rust 是比 Python 更接近底層的程式語言。這項改寫讓 Qiskit 的核心不必每次都回到 Python 解譯器，因此在處理大型電路時節省時間。官方舉例，400 量子位元電路的建構時間與 v1.0 相比，加快近 2.8 倍。

IBM 官方宣稱，雙量子位元么正矩陣合成方法在 v1.2.0 相較 v1.0.2 有近 100 倍改善、相較 v1.1.1 近 5 倍；其中一種 Clifford 合成演算法 synth_clifford_greedy 相較 v1.1.1 與 v1.0.2 近 500 倍。

這些倍數來自官方在自己程式碼範例中的測量，基準是 10,000 個隨機么正矩陣的平均執行時間。實際使用者的效果取決於工作負載，倍數越大的項目通常對應原本很慢的環節，不代表整體編譯流程同比例加速。

IBM 官方表示，轉譯器在優化等級 2 與 3 的初始化階段，於佈局與路由之前加入雙量子位元么正 peephole 優化，並新增 Split2QUnitaries 轉譯步驟，把可以分解成兩個單量子位元閘的雙量子位元區塊拆開。

先合併再最佳化的好處是減少閘數，簡化後續的佈局與路由問題；路由後加入的交換閘會打斷原本可合併的區塊，所以放在前面更容易找到較大的區塊。官方也在優化等級 2 調整了 Sabre 佈局與路由的起點選擇，並稱等級 2 將在 v1.3 成為預設。

IBM 官方表示，新增 QFTGate 類別以原生表示量子傅立葉轉換，並把合成延後到轉譯階段；另新增 random_clifford_circuit() 函式，並棄用未標版本的參考原語與 BackendV1，後者將在 v2.0 移除。

延後合成讓轉譯器能依硬體連線選擇更好的實作，官方提供全連接與線性鄰接兩種合成外掛。對開發者的實際影響在棄用項目：用到未標版本原語或 BackendV1 的程式需要遷移。

IBM 官方表示，v1.2 是最後一個支援 Python 3.8 的版本，v1.3 起最低需求為 Python 3.9；v1.3 也會把 transpile() 的預設優化等級從 1 改為 2。

這是對所有使用者有直接影響的預告：沒有明確指定優化等級的程式在 v1.3 之後可能得到不同的轉譯結果。官方說明的理由是轉譯器進步後，等級 2 在執行時間與品質之間是多數使用者較佳的取捨。
