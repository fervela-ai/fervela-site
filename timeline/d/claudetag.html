Claude 進 Slack：一個頻道，共用一個同事

Anthropic 在官方產品頁推出 Claude Tag，讓 Claude 加入 Slack 當團隊成員。Enterprise 與 Team 客戶可先用測試版。

這是什麼

Claude Tag 是團隊在 Slack 把工作派給 Claude 的做法。人標記 @Claude，它用被授權的工具在背景執行，做完回討論串。官方視它為 Claude Code 更主動、更適合整隊共用。

三點帶走

  1. 同一個 Slack 頻道裡只有一個共用的 Claude，進度大家看得到，也能接續別人的對話；私訊才私下回。
  2. 官方宣稱的 65%，指的是自家產品團隊由內部版本寫成的程式碼。
  3. 測試版先給 Enterprise 與 Team，搭配 Opus 4.8。頻道、工具與詞元上限由管理員設定，主動通報要另開。

重點與分析

官方宣稱，Anthropic 產品團隊 65% 的程式碼，由自家內部版本的 Claude Tag 寫成。官方表示，標記 @Claude 已是他們內部完成工作的主要方式之一，並在工程以外也這麼用：追產品指標與資料、處理客服工單、找出難解錯誤。

通鑑判斷，65% 說的是 Anthropic 自己的產品團隊，而且是自家內部版本，不宜看成外面公司裝上測試版就會有同樣比例。官方文字沒有說明這百分比怎麼算，例如算不算事後修改、審查或退回，也沒有給工程以外用途的件數。值得觀察的是，寫程式、追指標、客服與找錯誤被放進同一種標記做法。可能的落差是，外面拿到的是測試版，官方文字沒有說它和內部版本相同。

官方表示，一個 Slack 頻道裡只有一個 Claude，與全員互動；別人看得到它在做的事，也能接續上一個人的對話。它跟著頻道累積脈絡，獲准後可從其他頻道與資料來源自動學習，但不會從私人頻道回報。私訊則用個人工具私下回覆。

通鑑判斷，這和各自開一個私密對話不同：進度與上下文在頻道裡大家看得到，也能接下去。對要交接的團隊，可能少掉把同一件事重講一遍。值得觀察權限。官方寫明，向其他頻道與資料來源學習要先獲准，而且不從私人頻道回報；私訊又走個人工具、私下回。可能的落差是，同事以為什麼都共享，實際仍看管理員開了哪些來源，以及哪一段是私訊。官方文字沒有說明，未獲授權時能讀到多少舊訊息。

官方表示，派任務後可以先做別的事；Claude 也能自己排程，以數小時或數天推進。若開啟主動通報，它會從頻道與已接工具，標出它認為對方可能需要的資訊，並追蹤停住未解的討論或任務。官方表示他們現在花更多時間同時派工給多個 Claude。
