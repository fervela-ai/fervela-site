Anthropic 把蒸餾攻擊的防線移到 Claude 的推理紀錄

Anthropic 說明如何阻止他人未經授權、大量擷取 Claude 的能力，也交代防禦措施對正常用戶的影響。

這是什麼

蒸餾攻擊是大量取得一個模型的回應，再用來訓練另一個模型模仿它。Anthropic 這次的防禦重點，是讓攻擊者更難取得 Claude 的完整推理紀錄，同時辨識與阻擋擷取行為。

三點帶走

  1. 官方宣稱，蒸餾者取得的資料量減少約 90～99%；這是初步證據。
  2. 推理摘要在官方所述的特定程式測試中，較完整推理紀錄不利於蒸餾訓練。
  3. 防禦可能影響整合程式、誤擋請求與特定被擋請求的計費。

重點與分析

官方宣稱，初步證據顯示，新方法讓蒸餾者取得的資料量減少約 90～99%。防禦重點幾乎都放在保護 Claude 的推理紀錄。

通鑑判斷，這個數字說的是攻擊者取得的資料量，不能直接解讀為蒸餾攻擊已減少相同比例，或別的模型無法再模仿 Claude。推理紀錄比最終答案更能呈現模型如何得出結果，因此限制其流出有實際意義；但資料量下降後，攻擊者能否改用其他資料維持訓練效果，仍值得觀察。

官方宣稱，在以 Claude Opus 4.8 紀錄訓練預訓練模型的測試中，使用完整推理紀錄時，SWE-bench Verified 得分為 80.4%；只用推理摘要時為 71.8%。

通鑑判斷，這組測試具體說明為何 Anthropic 要保護推理過程：即使仍提供答案與摘要，受訓模型在這項程式任務測試中的表現也較低。不過，差距來自特定訓練方式與特定測試，不能推成所有任務都會有同樣效果。對使用 Claude 的人來說，較精簡的推理內容也是防止能力被擷取所付出的取捨。

官方表示，攻擊者曾利用大量假帳號反覆嘗試取得完整推理紀錄。Anthropic 對特定模型限制新建立的 API 帳號修改先前對話脈絡，也限制推理紀錄在模型或組織之間流轉。

通鑑判斷，防禦已從辨識單次可疑提問，延伸到帳號、對話脈絡和資料存取權限。這符合官方描述的攻擊方式：一個帳號遭阻擋後，攻擊者仍可換帳號繼續嘗試。這些限制可能讓某些原本依賴跨對話或跨模型傳遞推理內容的整合方式需要調整；實際影響仍取決於開發者使用的模型與功能。

官方表示，部分正常用戶須更新整合程式；官方宣稱，少於 0.1% 的正常請求可能被誤擋。在誤判率低於 0.1% 的特定領域，包括蒸餾，被安全機制於 Claude 回應前擋下的請求也恢復計費。

通鑑判斷，這是使用者最需要留意的成本：防禦措施可能影響既有程式，而遭擋下的請求在特定情況下仍會產生費用。兩個誤判率數字各有條件，不能視為所有請求的共同保證。開發團隊若遇到請求突然被擋或帳單變化，值得檢查是否涉及防蒸餾機制，並把誤擋與計費納入服務監控。

通鑑怎麼看

通鑑判斷，這次更新顯示模型業者保護的不只是最終答案，還包括能幫助其他模型學習的推理紀錄。官方提出初步資料與具體測試，但整體防禦成效仍不能只靠單一百分比判定。對企業用戶，最直接的問題是整合程式能否繼續運作，以及請求被擋時如何查明原因與費用。
