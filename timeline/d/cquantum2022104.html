Amazon Braket 推出 Braket Pulse 脈衝層級量子程式｜AWS（Amazon Braket）｜10 月 20 日 事件進階

Amazon（AMZN） Braket 開放脈衝層級控制，研究者可繞過預設量子閘

過去在 Amazon（AMZN） Braket 上只能用預先定義的量子閘寫電路；從 10 月 20 日起，使用者可以直接排程控制量子位元的脈衝。

這是什麼

量子閘其實是由校準過的類比脈衝實作出來的。Braket Pulse 讓研究者跳過閘這層抽象，直接設計脈衝波形，用來自訂閘、抑制雜訊或測試錯誤緩解技術。

三點帶走

  1. Braket Pulse 開放 Rigetti（RGTI） Aspen-M-2 與 OQC Lucy 的脈衝層級控制。
  2. 以 OpenPulse／OpenQASM 3 為基礎，並開源 Python 套件 OQpy。
  3. 適用於自訂閘、動態解耦與錯誤緩解測試，但文章未給出效能提升數字。

重點與分析

官方表示，Braket Pulse 提供對兩家硬體供應商 Rigetti（RGTI） 與 Oxford Quantum Circuits（OQC）量子處理器的脈衝層級存取。

文章明確寫出可用裝置是 Rigetti（RGTI） 的 Aspen-M-2 與 OQC 的 Lucy，使用者可用 Braket SDK 與 API 執行脈衝、閘或兩者混合的程式。換句話說，這個功能目前只涵蓋兩個超導量子位元平台，並非 Braket 上所有裝置都支援。

官方表示，到目前為止在 Amazon（AMZN） Braket 上只能用預定義的量子閘寫電路，需要探索雜訊、錯誤緩解或類比量子演算法的研究者需要更深層的控制。

文章列出三種使用情境：改進基本操作（自訂閘、探索 qutrit 等新範式）、在電路中加入動態解耦序列或測試零雜訊外推、以及直接在脈衝層設計類比量子演算法以減少閘抽象的開銷。其中動態解耦與零雜訊外推，是量子錯誤處理文獻中常見的做法；Braket 現在讓使用者能在雲端硬體上直接試。

官方表示，Braket Pulse 以 OpenQASM 3 規格的語法擴充 OpenPulse 為基礎，引入 Port（實體埠）、Frame（參考框架）與 PulseSequence（脈衝序列）等概念。

文章附了 OQC Lucy 的範例：建立長度 100 奈秒、寬度 25 奈秒、振幅 0.1 的高斯波形，設定相位後播放，再讀出量子位元，執行 100 次得到 72 次 1、28 次 0。作者也提醒，脈衝層控制需要對交互作用量子系統與硬體設計有更深的理解，不像閘那樣把物理細節抽象掉。

官方表示，SDK 的脈衝模組建立在 OQpy 之上；OQpy 是 OpenPulse 的 Python 綁定，AWS 在此次發表時開源並回饋給 OpenQASM 專案。

文章提到，除了 Braket SDK，使用者也能直接用 OQpy 或 OpenQASM 3 在 Braket 上寫程式，AWS 稱此為強化不同函式庫與裝置之間的互通性。文章也介紹 pulse_gate() 可把自訂脈衝序列包成閘放進一般電路，用來比較自訂閘對演算法表現的改善；但文章的措辭是「可能更高的效能」，並沒有給出實測的效能增幅。

通鑑怎麼看

通鑑認為，這項更新讓量子雲端平台從「只提供閘」往「開放硬體底層」前進一步，對做錯誤緩解與自訂閘的研究者有直接用處；但目前只涵蓋兩個裝置，也沒有官方的效能對照，實際價值要看後續研究者的使用成果。
