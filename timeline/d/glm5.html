GLM-5｜Z.ai｜2 月 11 日 模型進階

GLM-5 把重點放在需要多步完成的工程任務

Z.ai 推出 GLM-5，主打複雜系統工程與長程 AI 代理任務。官方公布多項評測，也提供 API 與自行部署的使用方式。

這是什麼

GLM-5 是 Z.ai 的大型語言模型，目標是處理寫程式、使用工具及連續執行多個步驟的任務。它整合 DeepSeek 稀疏注意力技術，官方表示可在保留長篇內容處理能力的同時降低部署成本。

三點帶走

  1. GLM-5 主打複雜工程與長程 AI 代理任務。
  2. 官方評測顯示部分成績優於前代；看分數時也要看工具與題目條件。
  3. 可透過 API 使用或自行部署，實際成本與成效需要按使用情境測試。

重點與分析

官方表示，GLM-5 相較 GLM-4.5，總參數從 3550 億增至 7440 億，每次運作的參數從 320 億增至 400 億；預訓練資料從 23 兆增至 28.5 兆詞元。

通鑑判斷，這組數字說明 Z.ai 擴大了模型與訓練資料的規模，但參數變多不能直接換算成工作成果變好。每次運作的參數增幅也小於總參數增幅，讀者不必把總量理解成每次提問都要用上的運算量。選用模型時，仍應看它能否完成自己的任務，以及使用成本是否合適。

官方公布的 SWE-bench Verified 評測中，GLM-5 得分 77.8，GLM-4.7 為 73.8；兩者均以 OpenHands 執行，使用官方調整過的指令、200K 上下文視窗等設定。

通鑑判斷，這比籠統宣稱擅長寫程式更有參考價值：同一張表列出前代模型成績，也交代了執行工具與設定。不過，評測測的是指定題目和流程，不能保證模型接手公司的舊系統後也有相同表現。若要拿它協助開發，值得先用實際工作測試修改是否正確、能否接續處理問題。

官方公布的 Terminal-Bench 2.0 評測中，GLM-5 以 Terminus 2 執行得分 56.2；改用修正模糊指令的驗證版題目，得分為 60.7。

通鑑判斷，同一模型在題目說明修正後出現不同分數，提醒讀者留意評測條件，別只記住較高的數字。這項測試涉及在終端機完成任務，與 AI 代理連續操作工具的能力較接近；但分數仍不是交付品質保證。實際採用時，應檢查它遇到含糊要求時會如何判斷，以及每一步是否方便人員核對。

官方提供 Z.ai API 使用途徑；Hugging Face 頁面也列出透過 vLLM、SGLang 等工具自行部署 GLM-5 的方法。

通鑑判斷，使用途徑的選擇對企業可能比單項排名更實際。透過 API 可以先試用；自行部署則讓團隊決定如何配置運算資源與管理系統，但也需要具備部署及維護能力。官方表示稀疏注意力技術可降低部署成本，頁面文字卻沒有給出可直接套用到各家公司環境的費用，採購前仍須按自己的用量估算。

通鑑怎麼看

GLM-5 值得留意的地方，是 Z.ai 同時提出工程任務評測與自行部署路徑。通鑑判斷，評測顯示它在指定條件下較前代進步，但不同題目、工具與設定會影響分數。是否適合工作現場，仍要用自己的任務驗證成果與成本。
