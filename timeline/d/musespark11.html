Muse Spark 1.1 把 AI 代理的重點推向跨工具完成任務

Meta 發表 Muse Spark 1.1，展示它如何規劃工作、操作電腦，並依新資訊調整後續動作。

這是什麼

Muse Spark 1.1 是 Meta Superintelligence Labs 推出的多模態推理模型，設計重點是執行 AI 代理任務。它已在 Meta AI 應用程式與 meta.ai 的「思考」模式提供使用；開發者可透過 Meta Model API 公開測試版存取。

三點帶走

  1. 它主打跨工具執行任務，並能把工作分配給子代理。
  2. 訂餐示例展示了依新資訊調整的流程，商品刊登與程式除錯示例則展示了串接影像、截圖與操作介面。
  3. 官方示例與安全評估提供參考；實際可靠度仍須按使用情境檢查。

重點與分析

官方表示，Muse Spark 1.1 能先蒐集資訊、擬定計畫，再把工作交給平行執行的子代理；也能管理官方宣稱長達 100 萬詞元的脈絡，找回先前工作的資訊。

通鑑判斷：值得注意的是任務如何接續，而不只是一次回答能讀進多少文字。工作交給子代理後，主代理仍須掌握進度與關鍵資訊，才能把各段成果接回同一個目標。官方描述了這套分工與脈絡管理能力，但沒有提供一般使用者在長時間任務中的完成率；實際表現仍要看任務變動後，模型能否維持前後一致。

官方表示，模型操作電腦時，會判斷何時寫腳本較快、何時直接點選介面較簡單。晚餐聚會訂餐示例中，任務出現新資訊後，它會調整訂單。

通鑑判斷：這個示例呈現的能力是處理變動，而非照固定步驟一路點到底。訂餐過程若有新資訊，代理必須辨認哪些既有決定受到影響，再更新操作。對要跨網站或應用程式辦事的人，這比單一步驟的自動點選更有用。不過示例只能說明官方展示的流程，還不能據此推定它遇到各種網站與例外狀況都能穩定完成。

官方展示，模型可從手機拍攝的商品影片挑出可用照片、判斷商品資訊，再操作瀏覽器，代使用者建立 Facebook Marketplace 刊登內容。

通鑑判斷：這個例子把看懂影像與操作介面串成一件事。使用者提供的不是整理好的商品表格，代理得先從影片取得可用內容，才能接著填寫刊登頁面。這類流程若可靠，可能減少在照片、文字和網站之間反覆搬資料的工作。值得觀察的是，模型會如何處理影片裡看不清楚、無法確定的商品細節，避免把推測寫成刊登資訊。

官方展示，模型在 OpenCode 建立聊天網頁應用程式後，會用自動截圖找出畫面上的問題，追查相關程式、修正並驗證。Meta Model API 同時開放公開測試。

通鑑判斷：截圖、追查、修正與驗證連在一起，比只產生一段程式更接近開發工作的完整循環。API 公開測試也讓外部開發者有機會在自己的流程中檢查這種能力。官方提到內部程式評測有所進步，但網頁文字沒有列出具體分數；外部團隊仍需用自己的專案衡量修正品質、耗時，以及需要人工接手的地方。

官方表示，部署前依其安全框架評估了化學與生物、資安及失控風險，結果處於安全界限內；也表示模型對不可信資料中的提示注入有抵抗力。

通鑑判斷：代理能讀取外部資訊並操作工具時，安全評估會直接影響它適合承擔哪些工作。這些是官方公布的評估結論，不能當作所有情境都安全的保證。尤其跨應用程式的任務可能接觸第三方內容，使用者或開發者仍應按任務風險決定可交給模型的操作範圍，並參照官方提到的完整評估報告了解測試條件。

通鑑怎麼看

通鑑判斷：Muse Spark 1.1 的看點，是把規劃、看懂畫面、操作工具與檢查結果串成較長的任務。官方提供了具體示例，開發者也已有測試入口；但示例與官方評估還不足以代表各種實際環境的可靠度。下一步應看它在任務中途出現變動、資訊不明或操作失敗時，能否清楚回報並讓人接手。
