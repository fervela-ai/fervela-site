AWS 與 NVIDIA 推 EC2 P5：H100 執行個體與第二代 EFA 網路｜NVIDIA／AWS｜3 月 21 日 事件進階

AWS P5 把 2 萬顆 H100 串成隨租隨用的超級電腦

AWS 與 NVIDIA（NVDA） 在 3 月 21 日公布 EC2 P5 的細節，重點不只是 H100，而是讓上萬顆 GPU 一起工作的網路。

這是什麼

EC2 P5 是 AWS 以 NVIDIA（NVDA） H100 打造的雲端 GPU 執行個體。訓練大型語言模型要把工作分散到成千上萬顆 GPU，機器之間的網路速度往往成為瓶頸；EFA（Elastic Fabric Adapter）是 AWS 自行設計的高速網路介面，P5 是第一個用上第二代 EFA 的 GPU 執行個體。

三點帶走

  1. P5 每個執行個體 8 顆 H100、640GB 記憶體、3,200 Gbps 網路。
  2. 第二代 EFA 讓 UltraClusters 擴充到 2 萬顆 H100，最高 20 exaFLOPS。
  3. 官方預期訓練成本比上一代最多降 40%，雙方合作散熱與下一代伺服器。

重點與分析

官方表示，P5 每個執行個體配備 8 顆 H100，提供 16 petaFLOPS 混合精度效能、640GB 高頻寬記憶體與 3,200 Gbps 網路連線，網路頻寬是上一代的 8 倍；訓練時間最多縮短 6 倍，訓練成本預期比上一代最多降低 40%。

網路頻寬提升 8 倍，比 GPU 本身的提升幅度還大，說明 AWS 認為大模型訓練的瓶頸在 GPU 之間的通訊。訓練成本降低 40% 是 AWS 的預期值，前提是客戶能吃滿新硬體的效能。16 petaFLOPS 是混合精度的數字，和 NVIDIA（NVDA） DGX H100 用 FP8 計算的數字基準不同，不宜直接比較。

官方表示，P5 部署在名為 EC2 UltraClusters 的超大規模叢集中，具 petabit 等級的無阻塞網路；EFA 的作業系統旁路（OS bypass）硬體介面整合 NVIDIA（NVDA） GPUDirect RDMA，降低延遲、提升頻寬利用率，搭配 NCCL 通訊函式庫可擴充到 2 萬顆 H100，整體最高可達 20 exaFLOPS。

GPUDirect RDMA 讓 GPU 可以直接透過網路讀寫另一台機器 GPU 的記憶體，不必繞經 CPU 與作業系統，這是上萬顆 GPU 能有效協同的關鍵。NVIDIA（NVDA） 自己有 InfiniBand 網路產品（見 chip_2023-03_5），AWS 則採用自研的 EFA，這則顯示雲端巨頭在網路層保留自主技術，只在 GPU 上依賴 NVIDIA。

官方表示，P5 是 AWS 第五代搭載 NVIDIA（NVDA） GPU 的執行個體，距離首次部署 NVIDIA GPU 的 CG1 執行個體近 13 年；Anthropic、Cohere、Hugging Face、Pinterest 與 Stability AI 等客戶將用 P5 訓練大型模型。

客戶名單裡有 Anthropic、Cohere 這類大型語言模型公司，說明雲端 GPU 已是模型公司訓練基礎模型的主要來源。Anthropic 共同創辦人 Tom Brown 在稿中說目前大量使用 P4 執行個體，預期 P5 比 P4d 有明顯的價格效能優勢。Stability AI 則預期 P5 讓模型訓練時間最多再縮短 4 倍。

官方表示，H100 推出前，雙方在熱、電、機構領域的工程團隊共同設計伺服器，重點是能源效率；官方稱在部分 AI 工作上 GPU 通常比 CPU 節能 20 倍，H100 跑大型語言模型最高比 CPU 節能 300 倍。雙方已開始合作下一代伺服器設計、散熱技術與網路擴充。

這段點出 AI 伺服器設計的新重點：散熱與供電。GPU 功耗越來越高，伺服器的熱設計與電力配置要和晶片一起規劃，散熱因此成為晶片商與雲端業者共同開發的項目。20 倍、300 倍是和 CPU 比、限定特定工作負載的數字，屬於官方宣稱。合作範圍延伸到「散熱技術」，代表雲端業者與晶片商的合作已深入到機房硬體。

通鑑怎麼看

通鑑認為，P5 的重點在網路：3,200 Gbps 與 2 萬顆 GPU 的擴充能力，才是大模型訓練真正需要的。雙方開始合作散熱與下一代伺服器設計，也預告 AI 晶片的競爭將延伸到整個機房。
