Claude Sonnet 4.6｜Anthropic｜2 月 17 日 模型入門

Claude Sonnet 4.6 把長文件與電腦操作帶進日常工作

Anthropic 推出 Claude Sonnet 4.6，並將它設為免費與 Pro 方案在 claude.ai、Claude Cowork 的預設模型。

這是什麼

Claude Sonnet 4.6 是 Anthropic 的 Sonnet 系列模型。這次更新涵蓋程式、電腦操作、長上下文推理、代理規劃、知識工作與設計，本頁特別整理長資料、電腦操作和多步驟工作，讓使用者能把更多辦公任務交給 AI 協助處理。

三點帶走

  1. 免費與 Pro 方案已將 Sonnet 4.6 設為 claude.ai、Claude Cowork 的預設模型。
  2. 測試版的長上下文視窗，以及電腦操作能力，讓長文件和跨工具任務更值得嘗試；重要結果仍需核對。
  3. 早期偏好測試與 OfficeQA 成績各有適用範圍，不能視為所有工作表現的保證。

重點與分析

官方表示，Sonnet 4.6 提供測試版的 100 萬詞元上下文視窗，可在單次請求中放入整個程式專案、長篇合約或數十篇研究論文。

通鑑判斷，視窗變大，最直接的用途是減少拆分資料、反覆補充背景的工夫。例如比較多份合約或追查跨文件的資訊，使用者可以先提供較完整的內容，再要求模型找出差異。不過，放得下不等於每個細節都讀得準；官方也把這項功能列為測試版。處理重要文件時，仍應回到原文核對模型引用的段落與結論。

官方表示，早期使用者已讓 Sonnet 4.6 操作複雜試算表、填寫多步驟網頁表單，並整合不同瀏覽器分頁的資訊；官方也承認，它操作電腦的能力仍落後於最熟練的人。

通鑑判斷，這類能力值得注意，因為許多辦公流程分散在網頁和舊系統裡，未必有現成的自動化介面。若模型能透過畫面點選與輸入，就可能協助完成跨工具的工作。但這些是官方描述的早期使用情形，不能推成各種系統都能穩定操作。它也可能讀到網頁中企圖誤導模型的指令；涉及提交表單或更動資料的流程，應保留人工檢查。

官方宣稱，在 Claude Code 的早期測試中，使用者約 70% 的時候偏好 Sonnet 4.6 勝過 Sonnet 4.5；與 Opus 4.5 相比，偏好 Sonnet 4.6 的比例為 59%。

通鑑判斷，這組數字反映的是特定工具中的使用者偏好，適合用來理解長時間協作時的體驗，不能當成所有任務的能力排名。官方整理的回饋指出，受測者認為新版較會先讀背景再修改程式，也會把共用邏輯整合起來，而不是重複寫。對非工程師來說，值得觀察的是同一種工作體驗能否延伸到文件整理與多步驟任務，而非只看單次回答是否漂亮。

官方表示，Sonnet 4.6 在 OfficeQA 的表現與 Opus 4.6 相當；這項測試考查模型能否閱讀企業文件中的圖表、PDF 和表格，再據此找出事實並推理。

通鑑判斷，這比籠統宣稱模型更聰明，更接近上班族會遇到的工作：從不同格式的資料中找依據，再回答問題。若一個較容易取得的模型能做好這件事，整理報告、查找內部文件的使用門檻可能降低。不過，測試表現相當只限於 OfficeQA 衡量的任務，不能推論它在所有文件或所有推理工作上都與 Opus 4.6 相同。

通鑑怎麼看

通鑑判斷，Sonnet 4.6 的重點是把讀長資料、跨畫面操作和文件問答放進更多人的日常工具，而不只是提高一項測試分數。它已成為指定方案的預設模型，使用者較容易直接接觸這些能力。真正值得觀察的是：面對格式混雜的文件與需要多次操作的流程，它能否持續給出可核對的結果，並讓人清楚掌握每一步做了什麼。
