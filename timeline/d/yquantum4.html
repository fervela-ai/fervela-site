IBM 發布 Qiskit SDK v2.3｜IBM Quantum｜1 月 22 日 事件延伸

IBM 把量子電路的改寫權交給開發者

IBM Quantum 在 Qiskit SDK v2.3 的版本公告中，介紹 C 介面編譯、聯合量測與早期容錯運算相關更新。

這是什麼

Qiskit SDK 提供量子電路建構、編譯與最佳化工具。官方表示 v2.3 讓開發者可用 C 介面逐步檢視、修改並擴充編譯流程，也加入面向容錯量子運算（能自行修正錯誤的量子電腦）的指令與編譯功能。

三點帶走

  1. 開發者現在可透過 C 介面撰寫量子電路編譯中的自訂步驟，但該介面仍屬不穩定介面。
  2. 聯合量測有了專用指令，量測也能納入相關的電路轉換流程。
  3. 編譯速度因電路類型而異：硬體佈局選擇加快，控制流程編譯可能暫時變慢。

重點與分析

官方表示，新的 QkDag 物件與擴充的 QkTarget 物件，讓開發者能透過 C 介面撰寫自訂編譯步驟，逐步檢視、修改並擴充編譯流程，而不必重建整套編譯器。

量子電路編譯像替演出排座位：程式指定誰要互動，編譯器還得依照硬體上哪些位置能相連，安排實際執行方式。原文說明，過去 C 介面只能建立 QkTarget 讓 Qiskit 使用；這次則能寫出「讀取」QkTarget 的編譯步驟，並提供執行預設編譯階段（初始化、佈局、路由、轉換、最佳化）的函式。通鑑判斷，這次更新解開的是「能使用編譯器，卻難以改動其中規則」的卡關。官方稱這將帶來與自訂硬體、研究工具及獨立工作流程更深的整合；C 介面目前仍被官方明確稱為不穩定介面。

官方表示，新的 PauliProductMeasurement 指令可對多個量子位元做單次聯合投影量測；LitinskiTransformation 轉換也已延伸到量測。

聯合量測關心的是幾個單位之間的關係，不只是逐一讀取各自的結果。官方說明，這讓編譯到以 Pauli 運算為基礎的計算（PBC，容錯量子運算中常見的一種表示法）成為可能，並可與其他開源工具結合，形成端到端的編譯流程。通鑑認為，這項更新改變的是程式從「描述想算什麼」走向「交代設備該做什麼」的環節：量測如今能寫進指令，也能跟著電路一起轉換。研究者若要探索以量測為核心的運算方式，就多了一條較完整的編譯路徑。

官方表示，這版加入 Ross-Selinger（gridsynth）演算法來合成 RZ 旋轉，並改進 OptimizeCliffordT；新的 CommutativeOptimization 步驟能合併或刪除可抵消的閘。

量子電路的「閘」像食譜裡的一道操作；同一道菜若能少做幾步，執行所需的資源也可能跟著減少。官方稱，新的最佳化步驟利用閘的可交換性做更多抵消與合併，並降低 T 閘等高成本運算。通鑑判斷，IBM 在這裡走的是先把編譯工具備齊的路：官方也說這些工作是在為「完整容錯流程將來如何拼起來」預先演練，同時對現在的開發者有實際價值。接下來值得看的，是這些方法在實際研究電路中能省下多少昂貴操作；原文沒有給出量化數字。

官方表示，VF2Layout 與 VF2PostLayout 因升級與 Rust 效能改進而加快硬體佈局選擇；但 ControlFlowOp 轉為 Rust 的過程，可能讓含控制流程指令的編譯暫時變慢。

硬體位置的選擇，就像安排哪些同事坐在一起，讓需要頻繁協作的人少繞路。這次更新呈現兩種不同的速度變化，不能用一句「編譯全面加快」帶過。官方說明，ControlFlowOp 是內部資料模型最後一個需轉移到 Rust 的主要部分，這項轉換在 v2.3 已完成，但為了維持向後相容保留了部分 Python 行為，因此帶來暫時的額外負擔；官方預期後續版本會改善。通鑑認為，對正在使用 Qiskit 的團隊，最有用的做法是按自己的電路類型看結果：含控制流程的程式要留意等待時間。

通鑑怎麼看

通鑑認為，這版的核心是把量子電路編譯器變得更可改、更能處理未來的運算方式。自訂規則讓開發者接上自己的設備與研究流程；聯合量測和電路精簡工具則補齊另一端的指令需求。它的價值要看研究者能否用這些工具做出更合適、成本更低的電路。
