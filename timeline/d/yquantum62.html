Azure Key Vault Premium 預覽抗量子金鑰包裝｜Microsoft｜8 月 5 日 事件進階

抗量子遷移，先換保護資料金鑰的那把鎖

Microsoft（MSFT） 在官方技術文章中介紹 Azure Key Vault Premium 公開預覽的 AES 金鑰包裝功能，重點是讓服務替換容易受到未來量子電腦威脅的 RSA 包裝方式。

這是什麼

金鑰包裝就像把保險箱鑰匙另鎖進一個盒子：真正加密資料的是裡面的鑰匙，外層鑰匙負責保護它。Azure Key Vault Premium 現在提供 AES-KW，讓服務能改用抗量子方式保護這把資料金鑰。

三點帶走

  1. 抗量子保護不能只看資料怎麼加密，也要看資料金鑰怎麼保存。
  2. 改用 AES-KW 包裝既有資料金鑰，不必因此重加密整批資料。
  3. 功能已公開預覽；金鑰規格、權限設定與操作畫面仍是導入時要看的環節。

重點與分析

官方表示，資料通常由 AES 金鑰加密，外層再用 RSA 金鑰保護這把鑰匙；未來具備相關能力的量子電腦可能破解 RSA。Azure Key Vault Premium 已公開預覽 AES-KW，供服務替換外層包裝。

通鑑判斷，這次要解的卡關是「資料加密方式沒換，保護金鑰的方式卻可能先失守」。把資料想成鎖在保險箱裡，外層包裝就是保險箱鑰匙的收納盒；盒子被打開，裡面的鑰匙仍會暴露。這也是為什麼只看資料本身用了哪種加密演算法，會漏掉金鑰管理這一層。Microsoft（MSFT） 把替換點放在包裝金鑰的環節，讓原本使用 Azure Key Vault 管理金鑰的服務，有一條較具體的遷移路徑。

官方表示，遷移時可先用原本的 RSA 金鑰取出資料金鑰，再以 AES-KW 重新包裝；既有資料金鑰可以保留，已加密的資料也不必解開後重加密。

通鑑認為，最有實務價值的是改動範圍被縮小了。若企業必須先解開大量既有資料、換鑰匙再全部加密一次，遷移就會牽動資料庫、停機安排與操作風險。這裡改的是保護資料金鑰的外層，原本負責加密資料的金鑰仍可繼續使用。對管理 Azure SQL 等加密資料的團隊而言，討論焦點因此能從「要不要重做整批資料加密」移到「哪些服務使用 RSA 包裝、如何逐一換掉」。資料金鑰日後仍可另外輪替，但它不是這一步的必要條件。

官方表示，AES-KW 要搭配足夠長度的金鑰與妥善管理；在這個情境建議使用 AES-256，不建議 AES-128。服務也可分開授予金鑰包裝與一般加密操作權限。

通鑑判斷，換演算法只是遷移的一半，另一半是管住誰能使用金鑰。用生活中的門禁來說，能把鑰匙鎖進盒子的人，未必需要取得其他加密工作的權限；Azure Key Vault 將這些操作分開，管理者便能按工作需要授權並定期檢查。金鑰長度同樣不能省略：官方對這個情境指定較長的 AES 金鑰，說明「用了 AES-KW」並不足以描述完整的抗量子保護。企業若要盤點現況，應把包裝演算法、金鑰規格與存取權限一起列出，而不是只在設定表上改一個名稱。

官方表示，AES-KW 的 Azure Portal 畫面更新仍在進行，程式與設定檔已可使用；Managed HSM 則早已支援 AES 金鑰包裝，兩者的包裝與解包程式流程相同。

通鑑認為，這次進展主要改變的是既有 Azure Key Vault Premium 使用者的選擇。過去若要在 Microsoft（MSFT） 的金鑰管理服務中使用 AES 包裝，官方指出 Managed HSM 已有這項能力；現在 Premium 也提供公開預覽，原本使用共用服務管理金鑰、機密與憑證的團隊，多了一條在熟悉服務中試行的路。Managed HSM 仍是供高價值或合規敏感工作使用的專用服務，兩者定位沒有因此變成一樣。接下來值得看的是 Azure Portal 何時補齊操作畫面，以及這項功能何時走出公開預覽。

通鑑怎麼看

通鑑認為，這是一項務實的抗量子遷移進展：它把問題鎖定在保護資料金鑰的外層，讓服務有機會保留既有資料加密方式，逐步替換 RSA 包裝。企業最該先查的是哪些資料金鑰仍由 RSA 保護，再確認金鑰規格與操作權限。
