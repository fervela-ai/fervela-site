Claude 找出 Firefox 漏洞，真正的考驗是驗證與修補

Anthropic 與 Mozilla 合作，讓 Claude 檢查 Firefox 程式，並由研究人員確認問題、回報及修補。

這是什麼

這次合作顯示，AI 已能協助找出複雜軟體中的安全漏洞；但從發現異常到判定風險、完成修補，仍需要研究人員與軟體維護團隊接手。

三點帶走

  1. Claude 協助找出 Firefox 高嚴重度漏洞，但風險判定仍由 Mozilla 完成。
  2. 大量回報能擴大搜尋範圍，也需要人員篩選與驗證。
  3. 多數問題已進入正式更新；其餘修補與使用者安裝情況仍須分開追蹤。

重點與分析

官方宣稱，Claude Opus 4.6 在兩週內找出 Firefox 的 22 個漏洞，其中 14 個被 Mozilla 列為高嚴重度。

通鑑判斷，這個成果值得注意，因為 Firefox 是經過長期檢驗的瀏覽器，高嚴重度問題通常不容易找到。但找到漏洞的數量，不能直接當成 AI 已能獨立保障軟體安全的證據。嚴重度是 Mozilla 判定的；漏洞是否成立、影響多大，以及該如何修補，都需要後續查證。對使用瀏覽器處理工作的人來說，關鍵成果是問題能否及時修好，而不只是 AI 找出多少個。

官方宣稱，團隊掃描近 6,000 個 C++ 檔案，向 Mozilla 提交 112 份不同的回報；部分造成程式當掉的測試案例，最後未必與安全有關。

通鑑判斷，AI 可以擴大搜尋範圍，也可能把大量待查線索送進原本由人處理的流程。Mozilla 曾鼓勵 Anthropic 批次提交發現，即使尚未逐一驗證；這是在雙方討論回報方式後採取的做法，不能假設每個軟體團隊都能照搬。若沒有清楚的回報標準與負責篩選的人，回報量增加可能讓維護者更難分辨哪些問題需要先修。

官方宣稱，多數問題已在 Firefox 148 修復，並向數億使用者推送更新；其餘問題預計在後續版本修復。

通鑑判斷，這比單純展示 AI 找到漏洞更有實際意義：發現、確認、提交修補建議，最後進入正式更新，才構成使用者看得見的防護流程。不過，已推送更新不等於每位使用者都已安裝，也不代表所有回報都已結案。其餘問題仍待後續版本處理，顯示找得快與修得完是兩件需要分別追蹤的事。

官方宣稱，在數百次、約 4,000 美元 API 額度的測試中，Claude 只在兩個案例成功利用漏洞；測試環境移除了部分瀏覽器防護，包括沙盒。

通鑑判斷，找出漏洞與拿漏洞發動攻擊，目前呈現不同難度。這項測試證明 Claude 在特定條件下能寫出初步攻擊程式，不能推成它能直接攻破一般使用者的 Firefox。移除沙盒是重要但書，因為沙盒原本就是限制漏洞影響的防線。值得持續觀察的是，AI 找漏洞的速度提高後，防守方驗證與修補的速度能否跟上。

通鑑怎麼看

通鑑判斷，這次合作最有參考價值的不是單一數字，而是 AI 與軟體維護者如何接力：AI 大量搜尋可疑問題，研究人員核實與整理，Mozilla 判定風險並發布修補。這套流程已產生具體成果，也暴露大量回報需要篩選的成本。對企業而言，採用 AI 檢查系統時，應同時規劃誰來驗證發現、決定修補順序，以及追蹤更新是否完成。
