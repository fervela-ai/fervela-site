Gemini 多模態快速判斷 API｜Google｜11 月 11 日 產品推薦

AI 不寫答案只打分，判斷變成便宜的零件

Google DeepMind 在開發者部落格推出 Decisions API，主角是不寫文字、只替選項打分的新模型 Gemini Decision 1。

這是什麼

Decisions API 讓程式把是非題、選擇題、評分題一次丟給 Gemini Decision 1，直接拿回機率與信心分數。對一般人代表客服、審核、理賠這類流程，可以先由便宜又快的 AI 過第一輪。

三點帶走

  1. Decisions API 不寫文字，只替選項打分，輸出不收費，成本只剩輸入。
  2. 信心分數讓人工審核只處理機器沒把握的灰色案件。
  3. 要看的是 Google Cloud 版本上線時間與第三方的校準評測。

重點與分析

官方表示，Gemini Decision 1 不是一個字一個字生成答案，而是在單次運算中替候選選項打分，回傳機率與信心分數。官方宣稱在最多 16K 詞元的上下文下，端到端延遲為 150 到 250 毫秒，每百萬輸入詞元 0.10 美元，輸出詞元不計費。

以前請 AI 做判斷，像請人寫申論題：它要先想、再寫一大段，你還得從文字裡挑出結論，又慢又貴。這次改成選擇題閱卷機，選項先擺好，模型只負責給每個選項打分。卡關的地方在於，AI 判斷放進即時流程（例如使用者按下按鈕就要反應）一直太慢，帳單也難預估，因為思考與輸出的詞元都要錢。官方說明沒有輸出詞元費、沒有變動的思考詞元帳單，也沒有另外的語音轉文字與文字辨識費，成本只剩輸入一項。150 到 250 毫秒大約是一次眨眼的時間，通鑑判斷這讓 AI 從事後分析工具變成流程中的即時關卡。

同一份輸入可混合文字、圖片、音訊、影片與 PDF，官方表示上限 256K 詞元，並可同時問最多 1,000 題。題型有是非、2 到 255 選一、分級評分，每題附 0 到 1 的信心分數。官方舉例：通話錄音搭帳號資料、掃描理賠單搭受損照片。

受影響最大的是每天要看大量資料的後台：客服質檢、理賠審件、內容審核。以前要嘛訓練專用分類器，要嘛每個問題各呼叫一次大模型，同一份資料被反覆讀取、反覆收費。現在共用輸入只計費一次，每題只多算自己的指令與標準，像是同一份卷子讓閱卷員一次回答一千個小題。信心分數更關鍵：它讓機器能說我沒把握，程式可以只把灰色地帶交給備援模型或真人，其餘自動放行。通鑑認為，這種分流會改變人工審核的角色，從逐件看變成只看機器猶豫的案件，工作量與人力配置都會跟著重算。

官方列出 Google 內部用法：Gemini Notebook 用它即時分流問題，官方宣稱日常查詢延遲最多降低 40%，複雜任務留給深度推理模型；CC 從 200 多個表情中挑出反應；Google 搜尋用它偵測針對 MCP 工具的對抗行為。

這是另一條路線。多數廠商讓大模型想得更深、更久；Google 在大模型前面加了一個小而快的櫃台，先判斷這題要不要動用大模型。比喻成醫院的分診護士：感冒不必掛院長的門診，疑難雜症才送專家。對上班族來說，這會讓日常查詢變快，而不是每個問題都等 AI 慢慢思考。這些案例都是 Google 自家產品，客戶只有內部團隊，這是全文唯一有爭議的地方：40% 這個數字沒有附測試條件，外部公司能否複製，要等第三方使用後才知道。

官方宣稱，在共用基準測試組上，Decisions API 搭配 Gemini Decision 1，比 Gemini 3.5 Flash-Lite 搭配 Interactions API 便宜近 5 倍。官方表示提供免費額度供原型開發，整合陸續推出到 OpenRouter、LangChain、Vercel 等，Google Cloud 版本即將支援。

接下來有兩件事決定它能走多遠。第一是 Google Cloud 版本何時上線：大型企業採購多半走雲端平台，沒有上雲，金融、保險這類最需要信心分數的行業很難正式導入。第二是外部開發者在自己的資料上量到的校準品質，也就是模型說有八成把握時，是否真的約八成會對。官方宣稱校準誤差最低，但那是自家基準測試的結果，真正有說服力的會是第三方評測。價格上，近 5 倍的差距是跟自家輕量模型比，比較對象與測試組都由 Google 選定，通鑑建議看價格時只當方向參考，重點是輸出不收費，讓大量判斷的成本變得可預算。

通鑑怎麼看

通鑑認為，這是 AI 從會寫轉向會判斷的分水嶺：企業流程裡大量工作其實是選擇題，不需要長篇答案。贏家是客服、審核、理賠等量大而規則明確的流程，輸家是只靠單次生成賣錢的小型分類器服務。想試的團隊可先用免費額度，拿自己的舊案件跑信心分數；要採購的，等 Google Cloud 版本與第三方校準評測。
