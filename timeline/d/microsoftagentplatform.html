Microsoft Agent Platform｜Microsoft｜6 月 2 日 產品進階

Microsoft 把 AI 代理接進企業的日常工作

Microsoft 在 Build 發表會介紹 Agent Platform，從建立、部署到在 Teams 使用，勾勒企業 AI 代理的工作流程。

這是什麼

Microsoft Agent Platform 是讓開發者建立企業 AI 代理的平台：在 GitHub 開發、部署到 Microsoft Foundry，結合企業知識與網路資訊後，供員工在 Teams、Microsoft 365 等工作入口使用。

三點帶走

  1. Agent Platform 串起 GitHub 開發、Foundry 部署與 Teams、Microsoft 365 使用入口。
  2. Microsoft IQ 負責提供企業工作脈絡；資料取得範圍與權限設定會影響代理的實用性。
  3. Scout 展示主動處理工作的方向，目前先提供給 Frontier 客戶。

重點與分析

官方表示，開發者可在 GitHub 建立 AI 代理，部署到 Microsoft Foundry，讓平台自動以最適合該工作的模型進行優化，並透過 Teams 或 Microsoft 365 提供使用。

通鑑判斷，這套設計最值得注意的是把開發、模型選擇和員工使用串成同一條路徑。對企業來說，代理能否幫上忙，除了回答得好不好，還取決於它能否取得適當資料、進入員工原有的工作流程，並受到管理。官方描述了平台如何銜接這些環節；實際效果仍要看企業接入資料與設定權限後的使用情況。

官方表示，Microsoft IQ 可讓代理結合企業與外部知識；其中 Work IQ 涵蓋郵件、文件、會議等工作脈絡，Fabric IQ 處理結構化業務資料，Foundry IQ 協助檢索。

通鑑判斷，企業代理的關鍵差異可能在於能否理解工作的來龍去脈，而不只是讀到單份文件。郵件、會議與業務數據分散在不同系統，若能適當串接，代理才比較有機會回答誰負責、事情進展到哪裡，以及下一步需要哪些資料。不過，能取得更多脈絡也提高了權限管理的重要性；各公司仍需決定代理可以接觸哪些資訊。

官方宣稱，Web IQ 回傳相關網頁段落的速度，接近次佳替代方案的 2.5 倍；官方並表示，它可供不同模型使用。

通鑑判斷，網頁檢索速度可能影響需要反覆查找外部資訊的代理，但速度不能單獨代表工作品質。企業還得看找回的內容是否相關、能否與內部資料正確搭配，以及代理最後如何使用這些資訊。官方文字提出了速度比較，沒有交代比較所用的測試條件；這個數字適合當作產品主張，還不足以推算員工能省下多少時間。

官方表示，Microsoft Scout 以 OpenClaw 和 Work IQ 為基礎，先提供給 Frontier 客戶，可主動處理會議準備、行程衝突與例行工作；後續才會擴大推出。

通鑑判斷，Scout 讓 Agent Platform 的用途變得具體：代理不只等待員工提問，也可能依工作脈絡提醒並處理待辦事項。會議和行程牽涉多人安排，主動處理是否可靠，值得觀察。官方目前提到的是特定客戶可使用的產品，以及未來擴大的計畫；不能因此推定所有 Microsoft 365 用戶都已能使用相同功能。

通鑑怎麼看

通鑑判斷，Microsoft Agent Platform 的主軸是讓企業把自己的知識和工作流程交給 AI 代理使用，再透過員工熟悉的入口提供服務。這比單獨推出一個聊天工具更貼近企業導入時要處理的問題。平台描述已相當完整，但能否帶來穩定的工作成果，仍取決於資料接入、權限設定，以及代理在真實任務中的表現。
