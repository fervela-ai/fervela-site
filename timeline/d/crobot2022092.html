Code as Policies：用語言模型直接寫機器人策略程式

論文表示，只要給幾個「指令加對應策略程式碼」的範例，語言模型就能為新指令重新組合 API 呼叫，寫出新的機器人策略。

這是什麼

這是把「寫程式的大型語言模型」當成機器人大腦中的策略產生器的研究。人用自然語言下指令，模型輸出可執行的程式碼，程式碼再去呼叫感知與控制函式。

三點帶走

  1. 論文表示：語言模型可依自然語言指令與少量範例，重組 API 寫出機器人策略程式。
  2. 作者宣稱：階層式程式碼生成在 HumanEval 解決 39.8% 問題，那是程式基準而非機器人成功率。
  3. 摘要列出能力（空間推理、泛化、行為常識），但未給機器人任務的成功率數字。

重點與分析

論文表示，以程式碼補全訓練的大型語言模型能從註解（docstring）合成簡單 Python 程式；作者發現這類模型可以被重新用來依自然語言指令寫出機器人策略程式碼。

這是論文的核心想法：不另外訓練機器人專用模型，而是借用已經會寫程式的模型。好處是能直接利用程式語言的結構，也就是迴圈、條件判斷與函式，來表達機器人行為。需要留意的是，這種方式的可靠度取決於底層感知與控制函式庫是否完整，模型只負責「組裝」。

論文表示，策略程式碼可以表達處理感知輸出（例如物體偵測器的輸出）並設定控制原語 API 參數的函式或回饋迴路。給定幾個以註解格式寫成的語言指令及對應策略程式碼（少樣本提示），模型能接收新指令並重新組合 API 呼叫，產生新的策略程式碼。

少樣本提示意味著不需要為每個新任務重新訓練。這降低了使用門檻，也讓機器人行為變得可讀、可除錯，因為輸出是程式碼而不是黑盒的動作數字。反過來說，這也代表模型只能做 API 提供的動作；官方摘要沒有說明遇到 API 沒有的能力時會如何。

論文表示，藉由串接經典邏輯結構並引用第三方函式庫（如 NumPy、Shapely）做算術運算，這樣使用的模型寫出的機器人策略可以：一，展現空間與幾何推理；二，推廣到新指令；三，對含糊描述（例如「更快」）依情境給出精確數值（例如速度），也就是行為常識。

「更快」要變成多少公尺／秒，傳統程式必須人工寫死；這裡由語言模型根據情境推斷。這是摘要最吸引人的主張之一，但摘要只描述能力，沒有給成功率數字，因此「推斷得準不準」要看全文實驗，本文無法從摘要判斷。

論文表示，Code as Policies 是以機器人為中心的語言模型生成程式（LMP）表述，可表示反應式策略（例如阻抗控制器）與路徑點式策略（視覺式取放、軌跡控制），並在多個真實機器人平台上展示。其核心是提示階層式程式碼生成（遞迴定義未定義的函式），能寫出更複雜的程式，並把 HumanEval 基準上解決問題的最佳水準提升到 39.8%。

階層式生成的作法是：先寫出高層程式，裡面用到還沒定義的函式，再遞迴地請模型把這些函式補完。39.8% 是程式生成基準 HumanEval 的結果，不是機器人任務的成功率，讀者要分清楚這兩種數字。論文以多個真實機器人平台展示，但摘要沒有列出平台名稱或每個平台的任務數。

通鑑怎麼看

通鑑認為，Code as Policies 的意義在於把大型語言模型接上機器人的方式變得可讀、可組合：輸出是程式，不是黑盒動作。它與同月的 ProgPrompt 都走「語言模型加程式」路線。但摘要沒有給機器人任務成功率，39.8% 又是程式基準的數字，讀者不宜把它當成機器人能力的指標。
