IBM 發布 Qiskit SDK 2.2：C 語言轉譯函式與容錯編譯工具

IBM 在 2025 年 10 月 20 日發布 Qiskit SDK v2.2，最大更新是可從 C 直接呼叫的獨立電路轉譯函式 qk_transpile()。

這是什麼

Qiskit 是 IBM 的開源量子運算軟體開發套件。轉譯（transpile）是把量子電路改寫成特定硬體能執行的形式。超級電腦社群常用 C、C++ 等編譯語言，過去 Qiskit 要靠 Python，這次補上 C 端的轉譯功能。

三點帶走

  1. Qiskit SDK 2.2 新增可從 C 呼叫的 qk_transpile()。
  2. 新增 Litinski 轉換與角度範圍支援，轉譯平均快 10% 至 20%。
  3. 2.3 版（12 月）將不再支援 Python 3.9，並降級 Intel（INTC） Mac 支援。

重點與分析

官方表示，v2.2 新增 qk_transpile()，可在純 C 環境轉譯用 C API 建立的電路，不需要 Python 解譯器。

官方稱轉譯是讓完整量子工作流程能用 C 等編譯語言全程執行所缺的最後一塊。為了展示，團隊另做了一個以 C++ 實作 SQD 的量子加高效能運算範例，並稱 C++ 可說是高效能運算最受歡迎的語言。文章附了範例，把 10 個量子位元的 GHZ 電路轉到 100 量子位元的線性目標上，轉譯後出現 sx 31、rz 29、cz 16、x 6 個閘，這只是示範輸出，不是效能基準。

官方表示，v2.2 新增 LitinskiTransformation 轉譯步驟與無輔助位元的加法器、多控制 X 閘合成方法，用於容錯架構。

LitinskiTransformation 把只含 Clifford 與單量子位元 RZ 旋轉的電路，轉成多量子位元 Pauli 旋轉後接 Clifford 閘，來自 2019 年的論文。官方明說這「對大多數使用者近期不重要」，是為容錯量子運算鋪路。HighLevelSynthesis 也新增 optimization_metric，可選擇減少雙量子位元閘或 T 閘數。

官方表示，Target 模型可指定閘參數的角度範圍，並新增 WrapAngles 步驟，把超出範圍的角度改寫成硬體可執行的等價序列。

例子是 IBM Heron 系統的分數閘只支援 0 到 π/2 的 RZZ 角度，AQT 的 IBEX Q1 支援的 RXX 角度在 0 到 π/4。這讓 Qiskit 能更貼近真實硬體限制。官方也提醒登錄回呼函式的路徑會在下一個小版本改變，但會維持向後相容。

官方表示，使用 Benchpress 基準，電路轉譯平均快 10% 至 20%。

官方歸因於更多程式改寫成 Rust，編譯器找到更多最佳化機會，但也坦言「確切因素不明顯」。升級須知包括：最低 Rust 版本從 1.79 升到 1.85；2.2 是最後支援 Python 3.9 的版本，12 月的 2.3 起需要 Python 3.10 以上；Intel（INTC） Mac 支援層級將在 2.3 降級；多個電路庫類別將於 Qiskit 3.0 移除。

通鑑怎麼看

通鑑認為這是一則軟體版本更新，價值在於量子工作流程要進入超級電腦常用的語言環境。10% 至 20% 的速度改善有基準名稱可查，但屬官方自測。
