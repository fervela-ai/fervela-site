AWS KMS 開放 ML-DSA 後量子數位簽章，沿用既有 API

AWS 在安全部落格宣布，FIPS 204 標準的 ML-DSA 已整合進 AWS Key Management Service，使用者可用原有的 CreateKey、Sign、Verify 呼叫建立後量子簽章金鑰，簽章運算在 FIPS 140-3 Level 3 認證的硬體安全模組內進行。

這是什麼

數位簽章用來證明軟體、韌體或文件確實出自某人且沒被改過，目前常見的 RSA、ECDSA 簽章理論上可能被未來夠大的量子電腦破解。ML-DSA 是美國 NIST 標準化的後量子簽章演算法，這次 AWS 讓客戶不必自建系統，就能在雲端金鑰管理服務裡產生並使用這類金鑰。

三點帶走

  1. AWS KMS 以相同的 CreateKey、Sign、Verify API 支援 FIPS 204 ML-DSA，運算在 FIPS 140-3 Level 3 硬體安全模組內。
  2. 提供 ML_DSA_44、65、87 三種金鑰規格，訊息超過 4096 位元組要用外部 mu。
  3. 發布時僅 N. California 與 Milan 兩區可用，其餘商業區域數日內跟進；簽章格式的函式庫支援可能尚未齊全。

重點與分析

官方表示，ML-DSA 現已正式上線，發布當天可在 US West（N. California）與 Europe（Milan）兩個區域使用，其餘商業區域將在數日內跟進。

『發布時已在兩個區域提供』來自原文，並不是全球同步上線，其餘區域是承諾而非既成事實。對客戶而言重要的是不用改架構：金鑰仍透過 CreateKey、Sign、Verify 管理，只是金鑰規格與簽章演算法名稱換成新的。

官方表示，新增三種金鑰規格 ML_DSA_44、ML_DSA_65、ML_DSA_87，搭配簽章演算法 ML_DSA_SHAKE_256，分別對應 NIST 安全等級 1、3、5。

原文表格列出公鑰 1312、1952、2592 位元組，簽章 2420、3309、4627 位元組，可見等級越高，金鑰與簽章越大。與大家熟悉的 ECDSA 簽章只有幾十位元組相比，ML-DSA 簽章是千位元組等級，這會影響憑證鏈、嵌入式裝置與通訊協定的欄位設計，是導入時要實際評估的成本。

官方表示，使用 RAW 訊息類型時待簽訊息上限為 4096 位元組；更大的訊息需先在 KMS 外部算出 64 位元組的 µ（mu），再用新增的 EXTERNAL_MU 訊息類型送簽。

原文說 4096 位元組上限是為了降低回應延遲。外部 mu 的做法是先用公鑰雜湊與訊息前綴計算 SHAKE256，讓大型檔案不必整份送進 KMS。文中示範以 RAW 與 EXTERNAL_MU 對同一訊息、同一金鑰簽署，產生的簽章相同，所以兩種模式可互換。

官方表示，對於把長壽命信任根裝進硬體、或長期離線的裝置，簽章在出廠後很難更新，因此後量子準備對這類系統的整個運作壽命都很重要。

這解釋了為何簽章比加密更急著導入：韌體簽章金鑰一旦燒進產品就難以更換。但原文也坦白寫到，常見簽章格式如 CMS、COSE、UEFI 與 Open Titan 映像簽章，在撰文當時未必已有現成函式庫支援新演算法，所以實務上可能需要等生態系跟上。

官方表示，使用者也可以用 OpenSSL 3.5 在 KMS 外本機驗證 ML-DSA 簽章，以節省 KMS API 呼叫成本與配額。

範例以 JWT 為題材，header 的 alg 設為 ML-DSA-65，簽章用 KMS 內私鑰產生，公鑰以 DER 格式取出後用 OpenSSL 驗證。原文並提到 IETF 正在制定 ML-DSA 用於 X.509 憑證的標準草案，代表憑證體系的支援仍在標準化途中。
