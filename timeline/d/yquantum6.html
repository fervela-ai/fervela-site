AWS 說明蘇黎世區域可用的後量子密碼功能｜AWS｜1 月 9 日 事件延伸

AWS 的後量子保護，關鍵在連線兩端與服務設定

AWS 在蘇黎世區域的服務更新中，整理了當地可用的後量子密碼功能，以及啟用時需要誰採取行動。

這是什麼

後量子密碼旨在協助防範未來量子運算可能帶來的威脅。可以把連線想成寄送上鎖的文件：AWS 這次談的是如何換上更能抵抗未來攻擊的鎖，以及哪些連線會自動換鎖、哪些得由客戶設定。

三點帶走

  1. 蘇黎世區域已有多項支援後量子密碼的 AWS 服務，但啟用條件因服務而異。
  2. S3、CloudFront 等服務的自動保護，取決於連線的客戶端是否支援 ML-KEM。
  3. 企業還需分別盤點安全政策、程式庫與數位憑證，確認各條連線如何升級。

重點與分析

官方表示，AWS 已將標準化的 ML-KEM 後量子演算法整合進密碼程式庫，並用於蘇黎世區域可提供的多項服務；各服務的啟用方式不同。

通鑑判斷，這項進展解開的卡關是部署，而不只是選定演算法。企業連上雲端服務時，瀏覽器、應用程式和雲端端點都參與建立安全連線；只升級其中一端，使用者未必會走到新的金鑰協商方式。AWS 把同一套演算法帶進多種服務，讓企業有機會沿著既有系統逐步更換。真正費工的部分，則是盤點每條連線由誰管理、使用哪套程式庫，以及要在哪裡改設定。

官方表示，Amazon（AMZN） S3、Amazon CloudFront 等服務，在客戶端支援 ML-KEM 金鑰協商時可自動提供後量子保護；較新的 Chrome 瀏覽器是文中所舉的客戶端例子。

這改變了使用雲端服務的一個環節：服務端已備妥功能時，支援新方式的客戶端可以在建立連線時取得保護，服務使用者不必逐一替這些端點挑選安全政策。關鍵條件仍在連線另一端。企業如果有自建程式或較舊的連線工具，就需要查清楚它們是否支援 ML-KEM，才知道哪些流量能用上這項功能。對上班族來說，看到公司使用 S3 或 CloudFront，和確認自己那條資料傳輸受到保護，是兩個不同的問題。

官方表示，AWS Transfer Family、Amazon（AMZN） API Gateway，以及應用程式與網路負載平衡器，需要客戶選用支援後量子金鑰協商的安全政策；部分服務還需要更新程式庫或開發工具套件。

通鑑認為，這是企業最容易漏掉的一步。安全政策就像大樓門禁的通行規則：大樓備有新門鎖，不等於每一道門都已改用它。這些服務把選擇權留在客戶的服務設定，代表負責系統的人必須找出哪些對外入口、檔案傳輸與應用程式連線要調整，並檢查連線端能否配合。接下來最有用的進度數字，是企業實際完成設定、且客戶端成功使用新協商方式的連線比例，而不是可用服務的清單有多長。

官方表示，AWS Private CA 已支援使用 ML-DSA 的後量子數位憑證；文章另列出採用 ML-KEM 的連線金鑰協商功能。

這兩項工作處理的是不同問題。文章分別列出採用 ML-KEM 的連線金鑰協商功能，以及使用 ML-DSA 的數位憑證。通鑑判斷，AWS 同時列出兩條路線，讓企業能把後量子遷移拆成較清楚的工作：先盤點資料傳輸如何加密，再盤點憑證由誰簽發、在哪些系統使用。兩者牽涉的管理者與更換流程未必相同；分開處理，較容易找出真正卡住升級的環節。

通鑑怎麼看

通鑑認為，這次更新最有價值的是把後量子密碼從一個演算法名稱，變成可逐項執行的服務清單。AWS 已指出哪些連線取決於客戶端支援、哪些需要客戶改安全政策，也列出憑證這條工作線。企業下一步應沿著自己的資料傳輸路徑查設定與連線結果，才能把區域可用的功能變成實際保護。
