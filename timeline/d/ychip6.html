NVIDIA 公布 Rubin GPU 的 HBM4 設計｜NVIDIA｜1 月 5 日 事件推薦

Rubin 換上 HBM4，NVIDIA（NVDA） 要讓整座機櫃一起跑 AI

NVIDIA（NVDA） 在 Vera Rubin 平台技術說明中，公布 Rubin GPU 的記憶體與機櫃設計。

這是什麼

Rubin 是 NVIDIA（NVDA） 為大型 AI 系統設計的 GPU。這次的重點不只是一顆晶片變快，而是讓記憶體、處理器與晶片之間的連線配合，減少 AI 工作在等待資料時浪費的時間。

三點帶走

  1. 單顆 Rubin GPU 配備最高 288GB HBM4；官方稱其記憶體頻寬較 Blackwell 提升近三倍。
  2. Vera CPU 與 Rubin GPU 的共用資料池，瞄準跨處理器搬資料的負擔。
  3. NVIDIA（NVDA） 以整座機櫃為設計單位，重點是多顆 GPU 協作時的效率。

重點與分析

官方宣稱，單顆 Rubin GPU 採用 HBM4，記憶體容量最高為 288GB、頻寬最高為 22TB/s；HBM4 的介面寬度是 HBM3e 的兩倍。

可以把記憶體想成廚房旁的備料區：容量決定能放多少食材，頻寬決定一次能送多少到爐邊。AI 處理長篇文件或連續推理時，要反覆取用大量資料；只增加運算能力，資料送不過來，晶片仍得等。通鑑判斷，Rubin 換上 HBM4 的關鍵是同時擴大備料區與送貨通道。官方給的是單顆 GPU 的最高規格，讀這兩個數字時，也要分清容量與傳送速度各自解決的卡關。

官方表示，Vera CPU 與 Rubin GPU 之間透過 NVLink-C2C 連接，提供 1.8TB/s 的一致性頻寬；應用程式可將兩者的記憶體視為同一個資料池。

一致性記憶體像兩個工作區共用一份隨時更新的清單，省去反覆核對、搬運副本的麻煩。Vera CPU 負責資料與控制流程調度；應用程式也能將 CPU 與 GPU 記憶體視為同一個資料池。通鑑判斷，Vera 與 Rubin 共用資料池的價值，在於讓工作能更順暢地跨越兩種處理器；官方也點出，這種連接可支援把部分推理暫存資料移到 CPU 記憶體。實際影響會落在資料搬移是否減少，以及 GPU 能否少花時間等候。

官方表示，Vera Rubin NVL72 機櫃透過 NVLink 6 將 72 顆 GPU 連成一套系統；NVLink 6 提供 3.6TB/s 的 GPU 對 GPU 頻寬。

當一項 AI 工作分給許多 GPU，難處就像多人合寫同一份報告：每個人寫得快，仍可能卡在交換進度與整合結果。NVIDIA（NVDA） 把整座機櫃當成運算單位，正是要處理這個協作環節。通鑑認為，評估這套設計時，應看多顆 GPU 一起工作能否維持效率，而非只看單顆晶片的速度。這也解釋了為什麼 NVIDIA 同時介紹交換晶片、網路與處理器：工作規模變大後，連線就是運算能力的一部分。

官方表示，Vera Rubin 平台最初介紹 GPU、CPU、網路及基礎設施等六款新晶片；官方 2026 年 3 月 16 日更新稱平台已有第七款晶片，並維持對既有 CUDA 軟體的相容性。

這條路線把硬體當成一套設備來設計：GPU 負責運算，CPU 調度資料，網路負責讓各處理器交換成果。好處是各環節能配合設計；相應地，採用者評估的也會是整套系統的供電、散熱、維護與軟體銜接，而非只換一張運算卡。通鑑判斷，保留 CUDA 相容性是重要的一環，因為既有程式若能延續，導入新硬體的工作就能集中在系統配置與效能調整。Rubin 的競爭力，將取決於這些環節合起來的表現。

通鑑怎麼看

通鑑認為，Rubin 最值得看的進展，是 NVIDIA（NVDA） 把記憶體供料、處理器分工與機櫃內連線一起設計。AI 工作愈長、參與的 GPU 愈多，等待與搬資料就愈容易吃掉運算效益。HBM4 的容量和頻寬是起點，整套系統能否讓 GPU 持續有事可做，才是這條路線的核心。
