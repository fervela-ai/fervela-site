Claude Ship 把程式審查後的接力交給 AI

Anthropic 推出 Claude Ship，讓團隊設定規則，由 AI 接手程式變更的審查、修正與核准流程。

這是什麼

把拉取請求（PR）想成一張請同事檢查程式修改的單子。Claude Ship 讓 AI 處理這張單子送出後的審查、修正與核准判斷；哪些修改仍須人看，由團隊訂規則。

三點帶走

  1. Claude Ship 接手的是 PR 送出後的審查、修正與核准判斷。
  2. 團隊可訂政策，決定哪些修改由 AI 核准、哪些交由人審。
  3. 採用時要一起看等待時間與事後撤回比例，才能判斷流程是否真的改善。

重點與分析

官方表示，Claude Ship 結合已正式提供的 Code Review，以及測試版的 PR Steward、Claude Approvals，接續處理審查、修正和核准判斷。

通鑑判斷，這次真正想解的卡關是審查意見出來之後的反覆等待。寫程式的人可能已轉去做下一件事，卻得回頭修舊修改、再等檢查重跑，最後找人核准。單獨加快審查，只會讓意見更早出現；把後續修正也接起來，才可能縮短整段流程。對不寫程式的團隊來說，這像一份文件交出後，校對者不只圈錯，還能依要求改好並送到下一關。

官方表示，PR Steward 會處理檢查失敗、合併衝突及審查意見；每次送出修改後，都會說明改了什麼、如何撤銷。開發者也能指示它工作或停止。

通鑑認為，這項設計改變的是審查者與提交者的分工：審查者指出問題後，例行修補可先由 AI 接手，提交者再檢查處理結果。難處在於審查意見未必只有一種改法，修好一處也可能影響另一處。因此，逐次說明修改與撤銷方式很關鍵，讓人能追查並收回 AI 的處理。PR Steward 本身不核准或合併修改，責任仍留在團隊設定的流程裡。

官方表示，Claude Approvals 依團隊放在程式庫中的政策檔判斷：例行修改可由 AI 核准，指定情況則須更深入的人員審核。官方建議先用只觀察、不執行核准的模式。

通鑑判斷，Claude Ship 走的是把審查權限寫成團隊規則的路，而非讓 AI 對每張單子自行決定權限。政策檔像一份可執行的簽核表：先界定哪些修改可照表處理，再把需要人判斷的情況留下來。只觀察模式則讓團隊先比對 AI 的判斷與原有審查結果，找出規則寫得太寬或太窄的地方。能否用得安心，關鍵會是團隊能否把例外情況寫清楚。

官方表示，Claude Code 團隊在自身流程中使用 Claude Ship；其合併的 PR 數量從六月到九月增加超過一倍，同期合併後遭還原的 PR 比例下降超過四成。這是多層流程中的一環。

通鑑認為，這組數字值得看的是產出與返工能否一起改善：若合併速度提高，卻有更多修改事後被撤回，審查只是把問題往後推。Anthropic 提供的內部結果呈現了較好的方向，但這段流程還包含其他審查環節，不能把變化全算在 Claude Ship 身上。接下來最有用的觀察，是其他團隊採用後，能否同時維持較短的等待時間與較低的撤回比例。

通鑑怎麼看

通鑑認為，Claude Ship 的價值在於把 PR 送出後分散的工作串成一條可訂規則的流程。最值得團隊先試的是修正審查意見與只觀察核准判斷：前者處理反覆等待，後者讓團隊看清哪些決定適合交給 AI。
