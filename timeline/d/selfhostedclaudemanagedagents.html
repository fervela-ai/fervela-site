Anthropic 讓企業自己當 Claude 代理的房東

Anthropic 以私人測試版推出自建版 Claude Managed Agents。企業可在自己的雲端或機房跑 AI 代理，自己保管憑證與工作紀錄，並自選模型請求的去向。

這是什麼

這是 Claude 託管式 AI 代理的自建版：整套改放公司自己的雲端或機房，模型請求另選出口。代理要無人值守碰內部系統時，企業可以自己當房東。

三點帶走

  1. 整套 AI 代理可搬進公司的雲端或機房，自己顧伺服器、資料庫和工人程式，不只是把沙箱放進來。
  2. 安全靠格局：腦子和沙箱分開，憑證不進沙箱，網路可只放行少數主機，每一步留紀錄並送進既有監控。
  3. 私人測試版要向帳戶團隊申請；請求送到哪、有沒有人顧伺服器，決定它能不能在公司裡跑起來。

重點與分析

官方寫，Managed Agents 起先由 Anthropic 代管基礎設施；後來才加自建沙箱，讓程式留在自家。這次連控制層、沙箱、憑證、工作紀錄都放進公司的雲端或機房。企業自己運作伺服器、資料庫，以及執行指令和檔案工具的工人程式。

沙箱自建後，程式能留在自家，發令、鑰匙和工作紀錄仍在外面。代理要碰內部系統時，差的就是這三樣不在圍牆裡。通鑑認為，這次換的是房東，資安和管機房的人要看指令、密碼、紀錄是不是都在裡面。官方寫，工程師仍用代管版同一套核心介面。通鑑判斷，討論會轉成有沒有人顧伺服器、資料庫和工人程式，有機房人力才接得住。資訊部門得把它當成要排班顧的內部系統。

官方表示，代理接手更關鍵的工作：修好壞掉的建置、測試新版本、為警報分流、處理積壓的錯誤。它們無人值守跑在公司程式上，還得進入內部系統。官方寫，對有這種存取的代理，有些團隊要整套服務都在自家，不只沙箱；此前只能自己把平台做出來。

卡關在三條件疊加：跑得久、沒人在旁看顧、還要進內部系統。只把沙箱放在自家，像工具間留在公司，發令和紀錄仍在外面。官方寫，在這之前得自己把平台做出來。通鑑判斷，難在控制層、沙箱、憑證和工作紀錄要一起放進圍牆。官方也寫，這套服務為的是把長時間運行的代理送進正式環境。自建版把這層搬進雲端或機房，介面跟代管版相同，機器仍歸公司顧。

官方表示，無人值守不能靠人逐步檢查，限制要做進架構。官方以四原則設計，全代管、只自建沙箱、整套自建都適用。腦子呼叫 Claude，沙箱跑程式，兩者分開。發令、紀錄和密鑰留在沙箱外。MCP 工具和受支援介面，由沙箱外窗口把憑證加進請求。

通鑑判斷，這套設計走房子格局。主管留在房外決定下一步；臨時工要動手才進工具間。官方寫，沙箱用到工具才啟動，也不依賴同一間沙箱撐完全程。印章留在櫃檯，只有 MCP 工具和受支援介面由窗口蓋上；自建時可改放公司自己的密鑰管理。四原則原樣適用三種放法，差在房子是誰的。網路可收成允許清單，修建置的代理或許只留程式主機和套件庫；沙箱自己管，限制設在自己的防火牆。

官方寫，模型請求可送往 Anthropic、Amazon Bedrock、Google 的 Agent Platform、Microsoft Foundry，或自己的閘道。工作紀錄放在自家資料庫。現為私人測試版，須向帳戶團隊申請。

通鑑判斷，成不成卡在帳戶團隊開不開放測試權限，以及模型請求選哪個出口。官方寫，工作紀錄放在自家資料庫；若已與 Anthropic 約定零資料保留（不留下請求內容），送到 Claude 的請求比照其他 Messages API 呼叫。每一步的工具呼叫和回傳都留成紀錄，可經 OpenTelemetry 送進既有監控。通鑑認為，測試期間就看紀錄進不進自己的監控，出口停不停在公司點頭的那一側。

通鑑怎麼看

通鑑認為，這次的重點是代理要進內部系統時，誰當房東。Anthropic 從全代管、只自建沙箱，走到整套放進公司的雲端或機房。模型請求仍可送回 Anthropic，或送到三家雲端與自有閘道。官方的四個安全原則不因誰管機房而改寫，安全寫在格局裡。管得了伺服器、又要鑰匙和紀錄留在圍牆內的公司才對得上。私人測試版要過帳戶團隊；紀錄進不進既有監控，決定資安敢不敢讓它無人值守跑下去。
