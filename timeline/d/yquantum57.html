Google Cloud（GOOGL） 把後量子防護帶進自備金鑰的匯入流程

Google Cloud（GOOGL） 在 Cloud KMS 產品公告中，介紹預覽中的後量子安全金鑰匯入功能。

這是什麼

企業可以自行保管密碼金鑰，再匯入雲端服務使用。Cloud KMS 的新功能，是在金鑰送往雲端的途中，加上一層能抵抗未來量子電腦攻擊的保護；目前適用於軟體密碼金鑰的匯入。

三點帶走

  1. 新功能保護的是軟體密碼金鑰匯入 Cloud KMS 的傳輸過程，目前處於預覽階段。
  2. 客戶可沿用既有匯入流程，但須在本機使用受支援的程式庫包裹金鑰。
  3. 企業可搭配後量子密碼概況功能盤點金鑰演算法，再安排遷移。

重點與分析

傳統匯入方式會替傳輸中的金鑰加密。Google Cloud（GOOGL） 指出，攻擊者可能先截取並保存這些資料，等未來有能力的量子電腦出現後再解密；新方式改用抗量子攻擊的機制包裹金鑰。

可以把匯入想成把保險箱的鑰匙寄給雲端服務：保險箱本身再安全，寄送途中若留下可供日後破解的包裹，風險就已經產生。通鑑判斷，這項更新處理的是企業自備金鑰流程中容易被忽略的一段路，而非企業存在雲端的所有資料。它也說明後量子轉換為何得提早做：被截取的資料可以長期保存，攻擊者無須在截取當下就具備破解能力。

官方表示，新匯入方式沿用 Cloud KMS 現有的匯入工作流程：客戶建立匯入工作、取得公開金鑰，在本機包裹自己的金鑰材料，再交由 Cloud KMS 解開並匯入。

通鑑認為，沿用既有流程是這次更新最實際的設計選擇。企業換一種加密演算法，難處往往不只在演算法本身，還包括誰產生金鑰、在哪裡加密、如何交接，以及原有系統要改多少。現在客戶仍在本機處理自己的金鑰材料，再送進熟悉的匯入流程，負責雲端金鑰管理的團隊較容易把新保護放進既有作業。真正需要安排的工作，則集中在本機包裹金鑰的程式與操作程序。

官方列出 X-Wing、ML-KEM-768 與 ML-KEM-1024，供客戶選擇匯入時使用的金鑰封裝機制；本機包裹金鑰可使用 Tink 或 OpenSSL 等受支援的密碼程式庫。

金鑰封裝可以想成寄件雙方先約好一種上鎖方式，讓雲端服務能打開包裹，沿途取得包裹的人卻無法讀取內容。通鑑判斷，提供多種機制的價值，在於企業能依自己的密碼政策與現有程式庫選擇做法，無須把所有系統綁在單一路線上。相對地，選項也把決策交回使用者：安全團隊需要先確認既有工具支援哪種機制，再讓匯入端與 Cloud KMS 使用相符設定。

Google Cloud（GOOGL） 表示，Cloud KMS 的後量子密碼概況功能已正式提供，可依非對稱金鑰所用演算法顯示分類，協助客戶盤點遷移工作。

通鑑認為，匯入功能與金鑰盤點功能放在一起看，才比較接近企業實際的轉換工作：先看手上有哪些金鑰、使用哪些演算法，再決定新匯入的金鑰如何保護。只替新金鑰加上防護，管理者仍可能不知道舊系統分布在哪裡；只有盤點，卻無法改變下一次匯入的方式。這項進展讓企業有一個具體起點：檢查金鑰分類，並從需要自行匯入的軟體金鑰開始調整流程。

通鑑怎麼看

通鑑認為，這次值得注意的是 Google Cloud（GOOGL） 把後量子防護接進企業已在使用的自備金鑰流程。它同時處理傳輸中的保存後破解風險，並提供盤點現有金鑰的工具，讓遷移從抽象的安全目標變成可逐項執行的工作。
