Flexion Reflect v0：用語言模型指揮模組化機器人技能

Flexion 認為把每個情境都靠遙控資料教機器人是死路，改以「技能工具箱加基礎模型編排」的做法。Reflect v0 先拿「把玩具放進籃子」這個長流程任務示範。

這是什麼

Reflect v0 是 Flexion 的模組化自主性架構：頂層是 LLM/VLM 代理負責理解目標與選工具，中間是動作生成與導航、撿取等技能，底層是在模擬中用強化學習訓練的運動控制。文章是公司的技術介紹與路線圖。

三點帶走

  1. Flexion Reflect v0 以 LLM/VLM 代理編排模組化技能，而非單一端到端模型。
  2. 官方稱整理玩具的示範沒有硬編碼狀態機或遙控，流程由代理推理產生。
  3. 目前是機載控制加雲端推理，完全機載要等未來升級 Jetson Thor。

重點與分析

官方表示，為每種可能情境手動蒐集資料來訓練機器人是死路；現實太豐富且不可預測。Flexion 的做法是給機器人一個可重複使用、各自可靠的技能工具箱，再用理解世界的基礎模型來編排，並稱這樣的模組化避免脆弱的端到端巨型模型，介面清楚、可測試。

這是與端到端大型模型路線明顯不同的立場，對照近期 Figure、Sunday 等公司把重點放在資料與單一模型的說法，Flexion 選擇的是「分層」。優點是每層可以獨立測試與替換；代價是各層之間的介面要設計好。文章沒有提供與端到端方法的實測比較，因此這是設計主張，不是已證明的優劣。

官方表示，資料策略是不對稱的：盡可能利用模擬與合成資料，只在能補足特定缺口時才加入真實資料；示範任務是整理空間，把玩具撿起放進籃子，涵蓋感知、狀態估計、移動、操作與規劃，不使用硬編碼狀態機或遙控，整個流程由代理的推理產生。

「沒有遙控」是這篇的重點宣稱，意思是任務的順序由 LLM 代理用工具呼叫決定，而不是人寫死的流程。但示範本身是一個相對單純的任務；文章沒有給出成功率、物件種類或失敗案例，所以還看不出它面對更複雜環境的能力。

官方表示，底層是完全在模擬中以大量隨機化與擾動訓練的強化學習運動技能，包含可在崎嶇地形移動的感知式步態，以及可獨立指令骨盆高度與雙手目標位置的全身末端追蹤控制；上一層有導航與撿取技能，最頂層由 VLM 代理用開放詞彙分割辨識物體並在 3D 中持續追蹤。

這段說明了三層結構各自負責什麼，值得注意的是代理並不直接控制關節，而是呼叫偵測物體、移動、撿取、放下這些 API。這種設計把「想做什麼」與「怎麼做」分開，文章稱語言驅動意圖、物理限制可行性，但沒有討論當低層技能失敗時代理如何處理。

官方表示，目前系統結合機載控制與雲端推理：背包中的 Nvidia Jetson Orin 負責低階與高階控制迴圈、動作估計與 3D 場景理解，前方 ZED 立體相機提供 RGB-D 感測，VLM 代理在雲端；未來背包將升級為 Jetson Thor，以支援完全機載的推理。

這個架構意味著需要即時性的控制在本機，不影響安全的推理放在雲端，因此網路中斷時代理就無法決策。官方自己也把「完全機載」列為未來目標，等於承認現在的版本仍有雲端依賴。

官方表示，路線圖包括：能依多模態指令走過任何地形的統一 Transformer 全身控制策略、以擴散模型根據視覺預測短時程軌跡的動作生成器（讓開門、搬箱等互動行為成為可能）、能在 3D 空間中做區域與全域規劃的空間智慧，以及針對機器人 API 微調代理，並在模擬世界中部署加速學習。

這些是方向而非已完成項目：文章寫得很清楚這只是第一個應用。判斷進展時，應追蹤後續是否真的出現開門、搬箱等示範，以及官方之後發表的新版本；這篇本身只能說明 Reflect v0 的架構與一項示範。

通鑑怎麼看

通鑑認為，Reflect v0 的價值是把「LLM 當機器人的指揮官」這條路線具體化。真正的檢驗在於跨任務與跨環境的成功率，這篇尚未提供。
