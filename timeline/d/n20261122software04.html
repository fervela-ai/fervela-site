Microsoft SQL 四項模糊字串比對函式正式推出

Microsoft 宣布，四項原生 T-SQL 函式已正式推出，可衡量兩段文字的編輯距離或相似程度，協助找出拼字不同但字形接近的資料。

這是什麼

這些函式適用於 Azure SQL Database、Azure SQL Managed Instance、Microsoft Fabric 的 SQL database，以及安裝 CU11 或後續累積更新的 SQL Server 2025。Azure SQL Managed Instance 需使用 SQL Server 2025 或 Always-up-to-date 更新原則。

三點帶走

  1. 如果資料庫裡常有錯字或文字辨識錯誤，這些函式可能有助於找出值得檢查的候選資料。
  2. 高相似分數不等於資料相同，使用時仍需結合其他欄位判斷。

重點與分析

EDIT_DISTANCE 與 EDIT_DISTANCE_SIMILARITY 使用 Optimal String Alignment 演算法，分別回傳編輯次數與 0 到 100 的相似分數。

對需要容忍錯字的搜尋或資料核對，編輯次數可能比單純判斷文字是否完全相同更有用。

JARO_WINKLER_DISTANCE 與 JARO_WINKLER_SIMILARITY 衡量字元排列與共同開頭的接近程度；Microsoft 以 MARTHA 和 MARHTA 示範，相似分數為 96。

這種分數可能適合排列姓名候選結果，但共同開頭也可能讓不同名稱得到高分，仍需其他資料確認。

函式可直接在 T-SQL 中使用，無須外部程式庫、模型或自訂程式碼。Microsoft 列出的用途包括容錯搜尋、尋找可能重複的資料，以及核對文字辨識擷取的內容。

實際效果可能取決於先用業務資料縮小比對範圍，以及如何設定和驗證篩選門檻。

通鑑怎麼看

值得看的是，這項功能把常見的字形近似比對放進資料庫查詢流程。相似分數只能提供候選線索；兩筆資料是否指向同一人、商品或機構，仍取決於其他證據。
