Windows 把後量子密碼帶進企業現有的連線與憑證流程

Microsoft（MSFT） 公布並更新 Windows 後量子密碼功能，讓企業能從日常連線與憑證管理著手轉換。

這是什麼

後量子密碼是為了防範未來量子電腦破解現行加密而設計的新方法。這次進展的重點，是 Windows 開始把它放進安全連線、程式使用的密碼功能，以及企業核發憑證的系統。

三點帶走

  1. 需要保密多年的資料，應優先盤點其傳輸連線。
  2. Windows 已支援混合式 TLS 金鑰交換與複合式密碼功能。
  3. 在 Windows Server 2025 的 ADCS 中支援後量子憑證須另建憑證機構，可規劃與既有架構並行。

重點與分析

官方表示，Windows 已支援結合傳統密碼與後量子密碼的 TLS 金鑰交換，可用於 Windows 11 與 Windows Server 2025。管理員能透過既有的群組原則、裝置管理工具或 PowerShell 設定。

把 TLS 想成電腦傳送機密資料時，先和對方約定一把共同鑰匙的程序。難題是：有人可以先存下今天看不懂的加密流量，等未來有能力時再破解。混合式金鑰交換讓新舊兩套方法一起參與約定鑰匙，企業因而能先處理需要保密多年的資料。通鑑判斷，這項進展解開的卡關不只是演算法能否運作，而是管理員能否在既有 Windows 管理流程中安排測試與設定，逐步擴大到實際連線。

官方表示，Windows 密碼學 API 與憑證功能已提供複合式 ML-KEM、ML-DSA 支援，將傳統與後量子機制結合，供程式開發者測試金鑰交換、簽章與憑證用途。

密碼學 API 像是提供給軟體的共用工具箱。以前即使有新的後量子演算法，開發者仍須處理如何把它和現行機制安全地接起來；組合方式若各做各的，也增加整合出錯的機會。Windows 提供複合式功能，改變的是開發程式與設計憑證的環節：團隊可以在平台提供的介面上，檢查新憑證如何被核發、驗證與信任。通鑑認為，這比單獨公布一種新演算法更接近企業每天會碰到的轉換工作。

官方表示，Windows Server 2025 的 Active Directory Certificate Services 已能核發 ML-DSA 後量子憑證；既有憑證機構無法原地升級，企業須另建新機構，可與原有架構並行。

企業憑證機構像是公司內部的發證處，替系統與服務核發可供查驗的身分證明。這項功能讓後量子簽章進入發證流程，也讓企業面對具體的搬遷安排：新舊發證處可並行，哪些系統先改用新憑證、哪些驗證流程要調整，都得逐項規劃。通鑑判斷，不能原地升級是這則消息最有份量的實務細節；它把轉換從更新軟體的想像，變成企業必須配置新架構與測試信任關係的工作。

官方建議企業先盤點使用公開金鑰密碼的系統，優先處理須長期保密的資料，再於非正式環境測試混合式連線、憑證相容性與效能。

接下來決定轉換能否推進的，是企業能否找出哪些系統真的需要先改。官方列舉文件庫、郵件封存、資料庫與備份等長期保存資料的地方；這些系統若經由 TLS 傳輸，便是先盤點連線與憑證依賴關係的合理起點。通鑑認為，值得追蹤的具體進度，是測試能否走完從連線、核發憑證到驗證憑證的流程，並確認既有程式和設備可以互通。這比只計算企業啟用了多少新演算法，更能反映實際轉換的進度。

通鑑怎麼看

通鑑認為，Microsoft（MSFT） 這次最關鍵的進展，是把後量子密碼從演算法推進到 Windows 企業環境的連線與發證流程。企業可以沿用熟悉的管理工具測試，但發證處須新建，也說明這會是一項跨系統的搬遷工作。
