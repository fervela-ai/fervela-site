Quantinuum 推出 H 系列三項使用者工具：洩漏偵測、MCMR 量子位元重用、H2-1 模擬器｜Quantinuum｜7 月 12 日 事件進階

少用量子位元、先在模擬器試錯：Quantinuum 把三項工具交給使用者

Quantinuum 在 2023 年 7 月 12 日發文，說明三項讓企業與學術使用者更充分利用 H 系列量子電腦的工具，並列出它們在近期幾篇論文裡扮演的角色。

這是什麼

這是一篇產品與技術部落格。三項工具分別處理三個實務問題：量子位元「洩漏」到計算空間外造成錯誤、硬體量子位元不夠用、以及上機前要有一個像真機一樣會出錯的模擬環境來測試程式。

三點帶走

  1. Quantinuum 推出洩漏偵測小工具、MCMR 量子位元重用編譯套件與 H2-1 模擬器。
  2. MCMR 讓 20 個量子位元模擬 128 個格點的橫場伊辛模型。
  3. H2-1 模擬器以 NVIDIA（NVDA） cuQuantum 加速，與真機共用編譯器，可經 API 或 Azure 使用。

重點與分析

官方表示，「洩漏」是量子位元跑到計算子空間之外的錯誤過程，會明顯影響計算；Quantinuum 在 pyTKET 中開發洩漏偵測小工具，偵測並排除受洩漏影響的結果，也可用來量測單、雙量子位元的自發輻射率。

量子位元理論上只用兩個能階代表 0 與 1，但實體系統還有其他能階，量子位元跑到那裡就叫洩漏，一般的錯誤處理不一定抓得到。這個工具的做法屬於「錯誤偵測後丟棄」，和同日發表的氫分子實驗是同一種思路：發現有問題的結果就不用。文章說工具已在 2022 年 IEEE 研討會發表、開放原始碼，並在 pyTKET 的 GitHub 放了範例筆記本，所以這不是全新技術，而是整理成使用者可直接用的元件。

官方表示，MCMR 套件是 pyTKET 的編譯步驟，藉由在電路早期量測量子位元、重設後拿去別處重用，減少執行演算法所需的量子位元數；研究人員用它只以 20 個量子位元模擬 128 個格點的橫場伊辛模型。

這是三項工具裡最值得注意的一項。離子阱機器可以在電路中途量測並重設單一量子位元，MCMR 就是利用這個能力，讓同一顆實體量子位元在電路不同段落扮演不同角色。20 對 128 的例子說明效果可以很大，但前提是演算法結構允許「用完就丟」，例如文中提到搭配張量網路的電路；並非所有演算法都能這樣壓縮。文章也提到 H2 只有 32 個量子位元，兩個應用層級測試若沒有 MCMR 就放不進去。

官方表示，H2-1 模擬器使用 NVIDIA（NVDA） cuQuantum SDK 加速，採用真實的雜訊模型與參數，並與量子處理器共用同一套軟體堆疊與編譯器，讓細微且隨時間變化的錯誤也能被呈現。

模擬器的價值在於「像真機一樣出錯」。如果模擬器只算理想結果，使用者在上機前無法預估雜訊造成的偏差；共用編譯器則確保模擬時看到的電路就是上機時跑的電路。文章說這個模擬器在 H2 發表時以測試版推出，如今升級後支援分批執行工作、執行中取消、回傳部分結果等功能，H2 訂閱者可經 API 或 Microsoft Azure（MSFT） 使用。文中沒有說明它能模擬到多少個量子位元，只說接近傳統硬體做完整態模擬的極限。

官方表示，近期非阿貝爾拓撲序與任意子的實驗、改良版單層 QAOA 研究都使用了 H 系列模擬器做測試、除錯與實驗設計；MCMR 與洩漏偵測也用於 H2 的效能基準測試。

這一段把工具和論文連起來，作用是證明工具不是空談。不過要注意引用的論文多半是 Quantinuum 自家團隊的預印本，等於公司用自己的成果背書自己的工具。文章結尾把「好處」分成兩種：在 NISQ 硬體上擠出更多效能，以及提升研究人員的工作效率。對使用者來說，後者可能更實際：在模擬器上把程式除錯完再上機，可以減少排隊與機時成本。
