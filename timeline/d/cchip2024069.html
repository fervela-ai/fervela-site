Arm（ARM）：車用小晶片需要標準化

Arm（ARM） 車用事業副總在官方部落格說明小晶片為何適合軟體定義車輛。

這是什麼

小晶片是把一顆大晶片拆成多顆小晶粒，以先進封裝互連。Arm（ARM） 想提供共同架構，讓不同廠商的小晶片可以互通。

三點帶走

  1. Arm（ARM） 認為單片式車用晶片成本與複雜度正在上升。
  2. Arm（ARM） 與逾 20 家夥伴推動 Chiplet System Architecture。
  3. 文章屬倡議說明，未提供規格或時程。

重點與分析

官方表示，AI 軟體定義車輛的運算需求讓單片式晶片愈來愈複雜且昂貴。

ADAS、自駕與車載資訊娛樂都需要異質運算，這是 Arm（ARM） 提出小晶片作法的前提。文章沒有給任何成本數字，因此『更貴』是方向性說法。文章列出 ADAS、自駕與資訊娛樂三種用途，各自對運算與安全的要求不同，這是單一晶片難以兼顧的原因。

官方表示，小晶片可堆疊、分割並互連多顆晶粒，帶來更高密度、更高效能與更低功耗。

Arm（ARM） 稱這種先進封裝技術也降低設計成本，且可跨供應商。原文指出汽車市場的獨特挑戰之一是開發過程中取得車規資格認證，並認為小晶片能處理這類挑戰，但沒有說明具體做法。文章在此處沒有引用任何實際的車廠或晶片案例，所以這是方向性主張。

官方表示，Arm（ARM） 於 2024 年 3 月公布 2025 年的車用運算子系統（CSS），作為小晶片的基礎。

CSS 是預先整合並驗證的運算元件。這句話把 CSS 與小晶片綁在一起：Arm（ARM） 提供可重複使用的 IP，由夥伴組成更大的系統。官方說明 CSS 是一組整合的元件，分別負責不同運算工作並作為小晶片的基礎；它是設計起點而非成品。

官方表示，Arm（ARM） 參與 imec 主導的 Automotive Chiplet Program，並與逾 20 家夥伴推動 Chiplet System Architecture。

標準化目標是避免生態系碎片化，讓不同廠商的 CPU、GPU 與 NPU 小晶片能協同。20 家夥伴跨汽車、基礎設施與行動市場，但文章沒有列出名單，也沒有時程。官方稱標準化也有助於處理車輛攻擊面擴大的資安挑戰，這是汽車領域特別強調的理由。夥伴名單與時程都未在文中公布，目前能確認的只有計畫存在及參與家數。

官方表示，SOAFEE 以統一的軟體架構支援軟體定義功能，並讓硬體與軟體解耦。

硬體標準化需要軟體端的配合，否則小晶片仍會被特定軟體綁住。SOAFEE 是 Arm（ARM） 擔任重要角色的產業倡議，這句只是概念說明。SOAFEE 管軟體、小晶片標準管硬體介面，文章的主張是兩者缺一不可，但沒有提供任何採用進度。
