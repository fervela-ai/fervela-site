迴圈工程自學地圖

迴圈工程（loop engineering）的意思是：把自己從「一句一句下指令的人」換掉，改成設計那個會下指令的系統。五分鐘看懂它是什麼（前言＋下面那支影片）；認真跟著做，一週內跑起你的第一條有停止條件、有硬擋的迴圈（階段 0～2，每天約 1 小時）。要走到無人看管、自己驗收、會教別人，再往後走階段 3～6。這張地圖本身也是一條迴圈：每階段有要讀的、要做的、驗收標準，驗收不過就不進下一階。

前言：從提示工程到迴圈工程

以前談的是提示工程（prompt engineering）：每次寫一句盡量完美的指令，等模型回答，再寫下一句。

這條路不是一天冒出來的。2025 年 7 月，Geoffrey Huntley 公開了「Ralph」做法：用一個 Bash 迴圈，讓 AI 代理反覆跑同一份提示（Ralph）。2025 年底，Matt Pocock 的教學讓它流行起來（Pragmatic Engineer）。

2026 年 6 月初，三件事在幾天內接連出現：Claude Code 的創作者 Boris Cherny 說他不再直接提示模型，而是讓迴圈去提示，自稱工作就是寫迴圈；OpenClaw 的作者 Peter Steinberger 在 6 月 7 日發文，主張工程師該改去設計迴圈；Addy Osmani 寫了〈Loop Engineering〉，把這個做法整理成可以學的架構（Osmani、Machine Learning Mastery）。

誰最先用這個詞，各來源說法不一：有研究論文把它定在 2026 年 6 月初、由這三件事一起帶起來（arXiv 論文），也有文章把命名歸給 Osmani，但沒有哪篇一手資料說「是我先取的名」。所以這是個還很新、沒有標準定義的詞，也有人認為它只是舊的排程自動化換了名字（Pragmatic Engineer）。這張地圖把它當成一門可以練的技術。

明天就能開始：先看這一支

  1. 01
    IBM Technology — What Is Loop Engineering? （原文）
    10 分 48 秒、2026 年 10 月 19 日的影片，講法最白。看完你會有四站（目標、行動、觀察、調整）、一個判斷好壞目標的方法（有沒有停止條件），和人在迴圈裡剩下的三件事：寫有停止條件的目標、把意圖寫在代理找得到的地方、讀輸出。

先把定義講白

上面影片的四站，講的是迴圈「怎麼轉」；這裡的五件東西，講的是迴圈「要備齊什麼」。兩者大致對得上（目標↔目標值、行動↔動作、觀察↔感測、調整↔回授），多出來的「停止與升級」是影片只用「目標有停止條件」帶過、但實作時最常被漏掉的一件。缺哪一件，就是你下一步要補的。

迴圈的五件東西
  1. 目標值：要達到什麼，量得出來。
  2. 感測：程式怎麼量現在做到哪。
  3. 動作：誰去做下一步。
  4. 回授：做完怎麼驗。
  5. 停止與升級：預算用完、連續失敗、碰到該由人決定的事，就停下來交給人。
三個會被騙的地方
  • 「做完」是宣稱，不是證明，所以每階段的驗收都要拿證據。
  • 迴圈會慢慢偏離目標。
  • 詞元（token）成本會飆，要先設上限。
IBM 影片提的四個坑
  • 沒驗證的程式：沒有檢查就上線。
  • 理解債：系統裡的程式越多，人懂的越少。
  • 意圖債：代理知道系統做什麼，不知道為什麼。例：為了讓測試變綠，把折扣碼驗證放寬，對帳面是壞修法。
  • 認知投降：覺得「AI 做的一定對」。

七個階段

每階段都要「做」出東西、拿「證據」驗收。看完文章不算學會。量大的實作可以交給 AI，你只做設計和驗收。一週版＝階段 0～2（約 5 天，每天 1～2 小時）；階段 3 以後是進階。

階段 0　觀念一週版・約 1 天
  1. IBM Technology — What Is Loop Engineering? （原文） — 10 分 48 秒，最白的入門。迴圈四站：目標 → 行動 → 觀察 → 調整，繞回目標時問一次「做完了嗎」。目標要有停止條件：「讓結帳更快」量不了，「結帳的每個單元測試都過才停」才是。
  2. Anthropic — Building effective agents （原文） — 工作流（路徑先寫好）和代理（模型自己決定路徑）差在哪；五種工作流模式裡的「評估者與優化者」，就是一個做、一個評、循環到過。
  3. 本頁上面「先把定義講白」那一段（五件東西）

要做拿你手上三件重複做的事，各畫一張表：目標值／感測／動作／回授／停止與升級，缺的那格寫「缺」。

驗收不看筆記講得出四站、人的三件事、四個坑；每張表至少指出一個缺的格（最常缺的是「停止與升級」只寫在腦子裡、沒寫成程式）。

階段 1　單迴圈一週版・約 2 天
  1. Geoffrey Huntley — Ralph Wiggum as a software engineer （原文） — 最純的迴圈就是 while :; do cat PROMPT.md | claude ; done。每輪只做一件、每輪乾淨視窗、用測試擋壞程式、學到的寫進固定檔、用 git 存進度。作者自己警告：結果不確定，且只驗證過新專案。
  2. Claude Code 官方最佳做法（白話版） （原文） — 重點是「給它一個能跑的檢查」：沒有檢查，你就是檢查。本站把官方文件逐章整理成白話，可從這裡讀。
  3. Claude Code — /goal （原文） — 設一個可量的終點加怎麼證明，每回合由另一個小模型判斷「未達／達成／不可能」，沒進展會自己停；可以寫「或 20 回合後停」。

要做題一：在一份工作複本裡設 /goal 測試全過且 git status 乾淨，或 20 回合後停，走開，回來看證據。題二：把一件每天要做的小事寫成「提示檔＋進度檔」，裝上排程跑 3 輪。

驗收兩題都有「你不在場」的證據（判定紀錄、進度檔 3 行）；記下每題花的詞元與分鐘數，以及哪裡偏離、你怎麼改提示。

階段 2　硬停止與防護一週版・約 2 天
  1. Claude Code — hooks 指南 （原文） — 規矩只是勸告，hook 是確定會跑的腳本。事件有工具呼叫前後、停止前、送出訊息時；Stop hook 可以擋住「結束」直到你的腳本放行。

要做挑一條你一直叫 AI「不要這樣做」的規矩，寫成 hook；再做一個 Stop hook：這回合說「完成了」但證據欄是空的，就不准停。

驗收變異測試：故意違規三次，三次都被擋、紀錄檔有三行。再記下它誤擋了什麼正常動作、怎麼放寬。

階段 3　狀態與視窗進階・約 1 天
  1. Anthropic — Effective context engineering for AI agents （原文） — 視窗是「注意力預算」。長任務三招：壓縮後開新視窗、把進度寫進筆記檔再讀回、用子代理在乾淨視窗做細節只回摘要。
  2. Ralph 那篇的一句話：代理會忘，檔案不會。

要做把階段 1 的迴圈改成：狀態只放在進度檔，每輪從乾淨視窗讀檔開始。

驗收跑到第 2 輪中途把視窗殺掉，重啟後第 3 輪從檔案接上，沒重做、沒漏；每輪視窗詞元比改之前少。

階段 4　多代理、做驗分離進階・約 3 天
  1. Addy Osmani — Loop Engineering （原文） — 五要素：排程自動化、工作樹（平行代理各自一個目錄）、skill（知識檔）、連接器、子代理（做的人跟驗的人分開），外加「狀態存在對話之外」。作者的提醒：還早、要懷疑、詞元會飆、別對 AI 說的話照單全收。
  2. 官方最佳做法（白話版） （原文） — 寫手／審查者兩個視窗、對抗式審查（只報影響正確性的）、批量展開（用 claude -p 對一批檔案各跑一次，先試 3 個）。

要做讓第二個視窗專門驗收，做的那個不能判自己過；用批量展開處理一批同類資料（先試 2 份）；開兩個工作複本平行跑兩條迴圈，確認互不干擾。

驗收一週內「假完成被退回」的件數量得出來；批量結果你抽 3 份人工核對，錯誤率記下。

階段 5　迴圈的迴圈進階・持續
  1. Pragmatic Engineer — What is loop engineering （原文） — 適合事件觸發與定時；不適合全部。有人試了失望：會偏離、人在迴路反而好、成本高（後半付費，本表只讀到前半）。

要做定四個你自己的目標數字，每週固定一天量、只改一處；另列一張「不做成迴圈」的清單（對客戶、口味、方向、對外定稿這類）。

驗收四個數字連兩週達標；達標前不加新迴圈，先修舊的。

階段 6　教別人進階・持續
  1. 把每階段踩到的雷整理成一頁，就是講義。

要做找一個不會寫程式的朋友，照你的講義在他自己的事上跑出第一條迴圈（例：每天整理信箱）。

驗收他自己跑得出來、你沒有在旁邊補洞，才算教會。

怎麼不半途而廢

用迴圈的五件東西管自己的學習：

  1. 目標值：本階段的驗收條件。
  2. 感測：每天固定時間問自己「今天在階段幾、驗收過了沒」，寫一行進度。
  3. 動作：每天 1 小時，實作交給 AI，你做設計和驗收。
  4. 回授：驗收不過就把踩到的雷寫下來、重做，不是跳過。
  5. 停止：連三天沒動，就是迴圈卡住了，回頭縮小目標。
