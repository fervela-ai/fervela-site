一句話重點

掛鉤（hook）是在 Claude Code 生命週期的固定時間點自動執行的程式，讓「一定會發生」的事不再靠模型自己決定要不要做。

這篇在講什麼

這是官方的入門指南，說明如何在 Claude Code 工作流程中的特定時刻觸發自訂動作，例如編輯檔案後自動排版、執行危險指令前攔截、需要你回應時發通知、在結束前驗證成果。文中先帶你做第一個通知掛鉤，再列出常見範例，接著講輸入輸出、回傳碼、篩選條件、設定位置、進階的提示詞與代理人掛鉤，最後是限制與除錯。

重點整理

掛鉤是什麼、怎麼設定

  • 掛鉤是使用者自訂的動作，在生命週期特定點由 Claude Code 執行，提供確定性的控制。
  • 設定寫在設定檔的 hooks 區塊，每個事件名稱是裡面的一個鍵，內容含 matcher（篩選）與 hooks 陣列（含 type、command）。
  • 位置決定範圍：~/.claude/settings.json 是你所有專案；.claude/settings.json 是單一專案且可進版本庫；.claude/settings.local.json 不共享；另有組織管理設定、外掛的 hooks/hooks.json、技能與子代理人的前置欄位。
  • 在介面輸入 /hooks 可瀏覽已設定的掛鉤；設定 "disableAllHooks": true 可停用。

有哪些事件

  • 工作階段類：SessionStart、SessionEnd、Setup。
  • 提問與工具類：UserPromptSubmit、PreToolUse（工具執行前，可擋）、PostToolUse（成功後）、PostToolUseFailure、PermissionRequest。
  • 結束與子代理人類：Stop（Claude 回答完時）、SubagentStart、SubagentStop。
  • 其他還有 Notification、PreCompact、PostCompact、ConfigChange、CwdChanged、FileChanged 等。
  • 掛鉤類型除了 command，還有 http、mcp_tool、prompt、agent。

常見範例

  • 通知：用 Notification 事件，在 Claude 等你輸入時跳桌面通知，各作業系統指令不同。
  • 改檔後自動排版：PostToolUse 搭配 "matcher": "Edit|Write"，用 jq 取出檔案路徑再交給排版工具。
  • 保護檔案：PreToolUse 掛鉤執行腳本，路徑符合 .env 等保護模式就以代碼 2 結束，腳本需先 chmod +x。
  • 壓縮後重新注入背景：SessionStart 搭配 compact 篩選，把標準輸出文字加進脈絡。
  • 其他：設定異動稽核（ConfigChange）、切換目錄重載環境、自動批准特定權限提示。

輸入、輸出與回傳碼

  • 事件觸發時，Claude Code 把 JSON 從標準輸入（stdin）交給腳本，含 session_id、cwd、hook_event_name，工具事件另有 tool_name、tool_input。
  • 結束碼 0 代表沒意見，走正常流程（對 PreToolUse 並不等於批准）。
  • 結束碼 2 代表擋下，把原因寫到標準錯誤（stderr），多數事件會回饋給 Claude 讓它調整。
  • 想要更細的控制，結束碼 0 並輸出 JSON，例如 hookSpecificOutput 裡的 permissionDecision（allow、deny、ask）與 permissionDecisionReason。PostToolUse 與 Stop 則用最上層的 decision: "block"。
  • 一個掛鉤只選一種方式，別混用結束碼與 JSON。

篩選：matcher 與 if

  • matcher 依事件不同而比對不同欄位，例如工具名稱、SessionStart 的啟動來源；空白代表全部觸發。比對區分大小寫。
  • if 欄位用權限規則語法（如 Bash(git *)）同時看工具與參數，只對工具類事件有效。
  • 多個掛鉤命中同一事件時並行執行，PreToolUse 的結果取最嚴格者（deny 勝過 ask 勝過 allow）。

提示詞掛鉤與代理人掛鉤

  • type: "prompt" 把判斷交給模型，只回 "ok": true/false 與 reason。
  • 用在 Stop 時，ok 為 false 會把 reason 當下一步指示，讓 Claude 繼續做。
  • type: "agent" 能讀檔、跑指令再下判斷，例如結束前實際跑測試；文件標示為實驗性功能。

除錯

  • 掛鉤沒觸發：用 /hooks 確認事件與篩選正確。
  • 腳本出錯：用 echo '{"tool_name":"Bash",...}' | ./my-hook.sh 手動餵 JSON 並檢查結束碼。
  • JSON 沒效果：常見原因是欄位放錯層，或 shell 設定檔先印出文字，擠掉開頭的 {。
  • 想看細節：用 claude --debug-file 寫日誌，或在對話中輸入 /debug；按 Ctrl+O 可看轉錄中的掛鉤結果。

對學習者的意思

  • 寫迴圈時，想要「一定會做」的步驟（排版、跑檢查）放進掛鉤，比在提示詞裡叮嚀可靠。
  • 做「沒證據不准停」：在 Stop 掛鉤檢查證據（例如測試輸出、檔案是否存在），不足就回報 decision: "block" 並附 reason，Claude 會被迫繼續；證據齊全才放行。
  • 證據要可驗證：用 agent 類型實際跑測試，比單靠模型自述完成更有說服力。
  • 設計「出口」：務必讀 stop_hook_active 並在已觸發過時放行，避免無限卡住。
  • 先用手動餵 JSON 的方式測腳本，再接進迴圈，除錯成本最低。

要小心的地方

  • 連續擋下 Stop 達八次且中間 Claude 沒有任何工具呼叫，系統會強制放行，並顯示警告。可用環境變數 CLAUDE_CODE_STOP_HOOK_BLOCK_CAP 調高，但腳本本身仍應有收斂條件。
  • Stop 在每次回答結束都會觸發，不只是任務完成；使用者中斷時不觸發。PostToolUse 無法復原已執行的動作。
  • 篩選有盲區：Claude 也能透過 shell 指令改檔，只比對 Edit|Write 會漏掉；if 屬盡力篩選，硬性允許或禁止應用權限系統。掛鉤腳本以你的權限執行，上線前需審視；代理人掛鉤為實驗性功能，行為可能改變。
