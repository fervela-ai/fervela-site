把 Ralph Wiggum 當成「軟體工程師」來用

一句話重點

Ralph 是一種把提示檔（prompt）丟進無限迴圈、讓程式代理人（coding agent）每輪只做一件事的做法；它靠固定的規格檔、自動檢查與反覆調整提示來運作，作者認為它適合從零開始的專案。

這篇在講什麼

作者介紹他稱為 Ralph 的做法：用最簡單的 Bash 迴圈，一遍又一遍把同一份提示交給 AI 寫程式。文章說明每輪該怎麼控制範圍、怎麼讓上下文保持精簡、怎麼用測試擋掉壞結果、怎麼讓代理人把學到的東西留給下一輪，也坦白講了這招的限制。作者用它做出一個實驗性的程式語言，並說明自己如何邊觀察邊調整。

重點整理

最小迴圈寫法

  • 最純粹的形式就是一行：while :; do cat PROMPT.md | claude-code ; done。
  • 作者說這個做法「確定地很糟，卻身處不確定的世界」：缺點是確定、可預期的，所以能靠調提示逐步修。
  • 只要代理人沒有限制工具呼叫與用量，原則上都能套用。
  • 整個做法是單一程序、單一程式庫（monolithic），作者不贊成讓多個代理人互相溝通，覺得那像用不確定的零件拼微服務。

每輪只做一件事

  • 每一輪只處理一項任務，由 Ralph 自己判斷哪項最重要，作者主張要信任這個選擇。
  • 每輪開頭都載入同樣的核心資料：計畫檔與規格檔，讓起點固定。

乾淨、精簡的視窗

  • 上下文視窗（context window）大約只有 170k 詞元（token），越塞越滿，品質越差，所以要盡量少用。
  • 主視窗扮演排程者，把耗資源的工作（例如整理測試結果）交給子代理人（subagent）。
  • 建置與測試只讓一個子代理人跑，避免產生背壓（backpressure）式的卡頓。
  • 代理人用搜尋工具（ripgrep）常會誤判「這功能還沒做」，所以提示要明講：改程式前不要假設某項尚未實作。

規格與計畫放固定檔

  • 需求先和代理人長時間對話釐清，再由它把規格寫成檔案，一份規格一個檔，放進 specs 資料夾。
  • 待辦清單放在 fix_plan.md：讓 Ralph 讀規格與原始碼，找出 TODO 與佔位程式，排出優先順序。
  • 作者常把清單整個丟掉重生，並說自己不親自規劃，因為模型比他更懂編譯器之類的細節。
  • 控制點在於標準函式庫與規格：模型用錯寫法就改函式庫，做錯東西就查規格。作者提到他一個月後才發現自己的詞法規格（lexer）把同一個關鍵字定義了兩次。

用測試與型別檢查當背壓

  • 產生程式碼很便宜，真正的把關是自動檢查：測試、型別檢查器、靜態分析、安全掃描。
  • 選語言是取捨：型別越嚴格越能擋錯，但編譯越慢；動態型別語言要另外接靜態檢查。
  • 每次修改後只跑與該單元相關的測試，並要求 Ralph 寫下每個測試為什麼重要，因為之後的輪次看不到當時的思路。

禁止佔位實作

  • Claude 傾向寫假的、先放著的實作（placeholder）。提示要明確要求完整實作。
  • 作者承認早期它仍可能無視，建議另外跑幾輪專門找出並列出這些佔位。
  • 也可以讓系統能檢視自己的輸出，例如加日誌或檢查中間產物，讓迴圈回頭驗證自己。

學到的東西寫進固定檔

  • AGENT.md 記錄如何建置與執行專案，要求保持簡短，學到有用的事就更新。
  • 順手發現的臭蟲，不論是否與當前任務有關，都要修掉或記進計畫檔。

用 git 存進度

  • 測試通過就更新計畫，然後 git add -A、git commit、git push。
  • 建置乾淨時打標籤（tag），從 0.0.0 起，每次把修訂號（patch）加一。
  • 程式庫偶爾會壞到無法編譯，操作者得決定整個重置重來，還是寫新提示救回來。

作者的警告

  • 作者不會把它用在既有程式庫，只適合從零開始，預期大約完成九成。
  • 仍然需要資深工程師把關；他反對「工具能取代工程師」的說法。
  • 提示不是完美的，直接複製他的提示無法重現結果，因為提示是邊看輸出邊調出來的。他把這比喻成調吉他弦，看到壞行為就加一個「路標」。

對學習者的意思

  • 先練會「一輪一件事」：把任務切小，讓每輪結果可以單獨檢查。
  • 把規格、計畫、操作筆記存在檔案裡，而不是依賴對話記憶，每輪從同樣的起點開始。
  • 迴圈能不能放心跑，取決於有沒有自動檢查；先把測試與型別檢查備好，再談讓它自己跑。
  • 觀察輸出、發現壞行為就補進提示，這是持續的調整工作，不是寫一次就結束。
  • 每次成功就用 git 存下來，壞掉時才有退路。

要小心的地方

  • 作者明說這是從零開始專案的做法，不會用在既有程式庫，且大約只做到九成。
  • 結果帶有不確定性：可能重複實作、無視指令或偏離方向，需要人持續盯著調整，也不能照抄他的提示。
  • 文中的成本與成果是轉述的單一案例（作者說他教過的一位工程師，用 Ralph 加 Amp 做完一份 5 萬美元合約的 MVP，並測試與審查完，成本約 297 美元），他自己的實驗專案也坦承還不能上線。
