一句話重點

用 /goal 寫下一個「完成條件」，Claude 每做完一輪就由另一個模型檢查條件成立了沒，沒成立就自動接著做，不必你每一步下指令。

這篇在講什麼

這篇介紹 Claude Code 的 /goal 指令。你給它一個可以驗證的終點，例如「測試全過」，它會一輪接一輪地做下去，直到條件被判定達成、被判定不可能，或遇到需要你處理的錯誤才停。文件也說明條件怎麼寫、怎麼看狀態、怎麼取消，以及背景工作與錯誤時的行為。

重點整理

適合用在哪裡

  • 適合「大量工作、但終點可驗證」的任務：把模組遷移到新 API 直到測試通過、照設計文件做到驗收條件全成立、把大檔案拆小到符合大小上限、清空待辦議題佇列。
  • 同一個工作階段（session）一次只能有一個目標；再下一個 /goal 會取代舊的。

和其他讓工作持續的做法比較

  • /goal：上一輪結束就開始下一輪，由評估模型判斷何時停。
  • /loop：依時間間隔觸發下一輪。
  • 停止掛鉤（Stop hook）：每輪結束觸發，停止與否由你自己的腳本或提示決定；/goal 其實就是只在當前工作階段有效的簡化版。
  • 自動模式（auto mode）只省掉每個工具呼叫的確認，不會自己開下一輪；兩者可搭配使用。

基本指令

  • /goal <條件>：設定目標並立刻開始一輪，條件本身就是指示，畫面會出現 ◎ /goal active 與已執行時間。
  • /goal（不帶參數）：看狀態，包含條件、已跑時間、已評估輪數、詞元（token）花費與評估者最近一次的理由。
  • /goal clear：取消目標；stop、off、reset、none、cancel 也可用。執行 /clear 開新對話同樣會移除目標。
  • 目標不會改變權限模式；若要無人看管地跑，要在自動模式下使用，否則手動模式遇到未預先允許的工具仍會詢問。

條件怎麼寫

  • 評估者只看對話裡已出現的內容，不會自己跑指令或讀檔，所以條件要寫成 Claude 的輸出就能證明的事。
  • 好條件通常包含：一個可量測的終點（測試結果、建置結束碼、檔案數、空佇列）、一個明確的檢查方式（如 npm test 結束碼為 0）、以及不能動到的限制（如不得修改其他測試檔）。
  • 上限 4,000 字元。想限制跑多久，可在條件裡加上輪數或時間子句，例如 or stop after 20 turns。

評估與停止規則

  • 每輪結束，一個小型快速模型拿條件與對話判斷，回傳三種結果：未達成（附理由，Claude 以此為下一輪方向）、已達成（清除目標並記錄）、不可能達成（清除目標並記錄理由）。
  • 若 Claude 連續數輪都只回應評估者、沒有實際使用工具，迴圈會停下並警告，目標保留，等你下次輸入再恢復評估。
  • 可用 ANTHROPIC_DEFAULT_HAIKU_MODEL 換評估用模型，但這個變數也會影響其他用到小型快速模型的功能。評估成本通常遠低於主要工作。

背景工作與錯誤處理

  • 一輪結束時若還有子代理（subagent）或背景指令在跑，該輪不評估，等沒有背景工作的下一輪再評估。
  • 背景工作讓目標等待滿 30 分鐘就會進行一次檢查（check-in），之後間隔加倍，最多到首次間隔的四倍；可用 CLAUDE_CODE_GOAL_CHECKIN_MINUTES 調整，設 0 則關閉檢查與自動重試。互動模式下閒置時最多自動發起三次檢查。
  • 必須由你修好的錯誤會清除目標：驗證失敗（由 Claude Code 自行管理憑證時）、額度用盡、自動壓縮仍無法解決的上下文溢出、模型不可用；修好後要重新下 /goal。
  • 其他錯誤目標保留：暫時性問題（伺服器過載、斷線）自動重試，三次後暫停；重試也沒用的（速率限制、用量上限）則暫停。

續接與非互動模式

  • 恢復工作階段時，仍有效的目標會被還原，但輪數、計時與詞元基準會重置；已達成或已清除的不會還原。
  • 可用於非互動模式，例如 claude -p "/goal ..."，會一次跑到結束；建議加 --output-format stream-json --verbose 才看得到過程，Ctrl+C 可中斷。桌面版與遠端控制（Remote Control）也支援。

對學習者的意思

  • 寫迴圈的核心是「終點條件」：先想清楚什麼證據能證明完成，再讓機器自己重複，而不是靠人每輪推一把。
  • 條件要寫成「對話中看得到證據」的樣子，評估者看不到你的硬碟，只看 Claude 說了、貼了什麼。
  • 把停止條件分成成功、不可能、人工介入三種，並加上輪數或時間上限，是設計任何自動迴圈都該有的保險。
  • 做事的模型與判斷是否完成的模型分開，能降低「自己說做完了」的偏誤，值得在自己的迴圈設計中借用。

要小心的地方

  • /goal 依賴掛鉤（hooks）機制：若設定 disableAllHooks 為 true，或受管理設定限制只能用受管理掛鉤，就無法使用；工作區信任規則也與掛鉤相同。
  • 部分行為有版本門檻：檢查需 Claude Code v2.1.234 以上，閒置檢查需 v2.1.236 以上，互動模式的重試與暫停提示需 v2.1.269 以上；實際以你安裝的版本為準。
  • 評估者不會執行指令，條件若寫成 Claude 無法在對話中展示的事，就可能一直無法判定達成。
